# Issue 122: authored loudness and a minimal object/height renderer

Date: 2026-10-21. Branch: `feat/issue-122-loudness-objects`.
Implementation and local validation are complete; CI is not claimed locally.

## Implemented boundary

- Copied, optional first-match node/bus authored-loudness rules feed each
  actual routed bus once per quantum. Physical voices and release tails
  participate; virtual voices, unmatched voices and future starts do not.
  HDR remains explicitly opt-in. Music and host sources can report their
  own authored metadata through the existing bus setter.
- Allocation-free 2-16 speaker CPU reference panner consumes cluster
  centroids, dedicated directions, beds and membership crossfades, including
  height. Integrated event hooks and the combined system descriptor expose
  an optional borrowed-PCM quantum callback, independent of stereo.
- Rules and layout participate in checkpoint configuration fingerprints;
  voice/tail metadata and existing cluster fades restore exactly. Tests
  compare both stereo PCM and future speaker callback hashes after a
  partial-quantum save/load.
- Disabled HDR with authored rules and speaker output with clustering both
  preserve the normal stereo output bit for bit. The existing voice-policy
  trace hash remains `28b457861b3f619c`.

The minimal panner is not an HRTF/VBAP implementation or a platform object
API. Multichannel devices, calibration and LFE/bass management remain future
extensions. Voice captures remain the existing pre-pan/pre-bus signals;
bus beds and voice objects are alternative representations and combining
both intentionally includes both. See the integration guide for callback
threading, replay and partial-quantum delivery semantics.
