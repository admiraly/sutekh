## What was already there
The renderer already rendered into `R16G16B16A16_SFLOAT` and tonemapped (ACES or clamp, manual exposure) to sRGB, the
format is in the baseline check, and emissive had a per-material (`emissive_strength`) and per-instance
(`SuRenderObject.emissive`) multiplier. Missing: bloom, auto exposure, glare. Nothing about those was changed.

## New API (`include/sutekh/render.h`)
- `SuRenderPost post` at the end of `SuRenderFrameDesc` (zero = off; all existing frames unchanged). Flags
  `SU_POST_BLOOM`, `SU_POST_AUTO_EXPOSURE`; `bloom_threshold` (0 = 1), `bloom_knee` (fraction), `bloom_intensity`,
  `bloom_radius` (0 = 1), `bloom_levels` (2..8, 0 = 6), `auto_key` (0 = 0.18), `exposure_min/max` (0 = 1/32, 32).
- `SuRenderDeviceInfo.bloom`: HDR format filterable. When 0, post requests are ignored (plain tonemap).
- `SuRenderStats.bloom_levels_active`, `post_passes`.
- `su_fx_glare(buf, pos, size, streak, color, view)`: CPU helper, core + halo + 2 streaks (about 12 triangles). The
  "flag" is whether the host calls it (the demo's `--no-glare`).

## Design
Half-resolution chain A (down: 13-tap; level 0 applies threshold, soft knee and Karis weights; alpha carries log2
luma of the unthresholded taps) down to about 2 texels, chain B (up: 3x3 tent of the smaller level, radius-scaled, plus
A[i]). Every level is its own framebuffer/pass (`bloom_pass`, load DONT_CARE, final layout SHADER_READ_ONLY, explicit
dependencies). Output pass `post_bloom.frag` = (scene + B0 * intensity / levels) * exposure, then the same tonemap;
auto exposure = clamp(key / exp2(average log2 luma of the smallest A level)). Stateless, so deterministic; no temporal
smoothing (documented). Bloom off uses the original `post.frag` path untouched. Bloom adds ~12 render passes at
1080p; the up chain always runs at least one level when auto exposure alone is on (B0 must be valid to sample).
Too small a target (half size under 4 px) or a failed allocation turns bloom off for that target, no error.
Bug found by looking at the demo image and fixed: the HUD shaders read the output size from the post push constants,
so the bloom output pass must push them again before the HUD (`test_render_bloom` has a HUD check now).
