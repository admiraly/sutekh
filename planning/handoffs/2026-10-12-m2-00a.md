## API summary
- `su_ents_create(desc, &e)`: `SuEntsDesc{max_entities, initial_alive, external_ids}`. Capacity = max(initial, max_entities), at most `SU_LIMIT_ROWS`. Not rounded.
- `su_ents_destroy`, `su_ents_capacity`, `su_ents_chunk_count`, `su_ents_high_water`, `su_ents_alive_count`, `su_ents_retired_count`, `su_ents_free_count`, `su_ents_chunk_alive_count`.
- `su_ents_alloc(e, ext, &h)`: lowest free slot. `su_ents_despawn(e, expected)`: stale expected returns `SU_E_STALE_HANDLE` with no change.
- `su_ents_validate(e, h)`, `su_ents_handle_for_slot`, `su_ents_slot_alive`, `su_ents_slot_retired`, `su_ents_slot_generation`.
- `su_ents_get_external`, `su_ents_set_external`.
- `su_ents_next_alive(e, from, &slot)`, `su_ents_chunk_alive_bits(e, chunk, &words, &count)`.
- `su_ents_copy(dst, src)` (no allocation, same capacity), `su_ents_clone`.
- `su_ents_canonical_size`, `su_ents_canonical_write`, `su_ents_canonical_parse`, `su_ents_state_equal`.
- `su_ents_fault_set_generation(e, slot, gen)`: test seam only, not gated by a build flag.

## Complexity and allocation
- alloc: at most `ceil(chunks/64)` summary words plus 16 bitmap words of one chunk. Constant bound for `SU_LIMIT_ROWS` (977 chunks, 16 summary words). Amortized O(1) under churn. A summary-word hint keeps the scan start.
- despawn, validate, external-id get/set, handle helpers: O(1).
- copy, canonical write and parse: O(capacity) for the table, O(high_water) for the dump.
- All arrays are allocated in create, clone or parse. alloc, despawn, validate, copy and iteration never allocate.
- Canonical dump: 60-byte header, then 9 bytes per slot below high_water (u32 generation, u32 external id, u8 alive). Size = 60 + 9 * high_water. Header carries capacity, high_water, alive_count, retired_count and the policy name `lowest_slot`.
- Parser rejects: capacity over `SU_LIMIT_ROWS` (before any allocation), length not exactly the expected size, counts that disagree with records, alive byte not 0/1, generation 0 or 0xFFFFFFFF on alive slots, generation 0 or nonzero external id on dead slots, a top slot at high_water-1 that was never allocated.

## Deviations and ambiguities for the contract owner
1. The dump layout (per-slot record, header fields, policy field) is not specified by the contract. I chose it. The `SUWSTATE` v2 world dump and snapshot 0.2 must align with it or wrap it.
2. The fault seam rejects slots at or above high_water. That keeps dumps canonical. The contract does not say this.
3. Capacity 0 is allowed. The contract does not say whether an empty table is valid.
4. The parser rejects a high_water whose top slot is dead with generation 1. The contract does not state this rule, and I inferred it from the definition of high_water.
5. External ids are not checked for uniqueness. Fixture rejection of 0 is left to `su_world`, as r2 says.
6. Dead slots are canonically zero in the external-id column. Retired slots store external id 0.
7. Exhaustion from retirement is indistinguishable from capacity exhaustion: both return `SU_E_RESOURCE_LIMIT`.
8. Churn never reaches full capacity (`spawn_full=0`). Capacity exhaustion is covered by its own deterministic test, not by churn. This is a coverage gap in the churn test.
9. The clang ASan leg is unrun (runtime missing here). Re-run it where `libclang_rt.asan` is installed.
10. Snapshot 0.1 restore (slots 0..n-1 alive, generation 1) is the world layer's job. This table only exposes the building blocks.
