# Issue 140: worlds with several entity kinds (multi-table worlds)

Branch `multi-table-worlds`, two commits: the decision note (`docs/MULTI_TABLE_WORLDS.md`) and the implementation.
This is the first slice the issue allows: multi-table schema, per-table spawn/despawn/handles, per-table
hash/commit and digests, byte identity for single-table worlds. The cross-table `space3d` form is the recorded
follow-up (docs/MULTI_TABLE_WORLDS.md section 8, docs/SPACE3D.md section 1).

## Decision

Option (a), several tables per world. Each table is an independent `SuWorld` (own declared schema, capacity,
fixture, entity table); one host world owns 1..`SU_HOST_MAX_TABLES` (8) of them and steps them as one world: one
tick, one input record stream, one event log, one snapshot, one digest, one identity. Option (b), linked worlds,
needs the same container (routing, concatenated snapshots, folded identity) plus a rule for cross-child handles,
and does not reuse `SuWorld`'s roots; it is not cheaper in this code. Details and the API in
`docs/MULTI_TABLE_WORLDS.md`.

Handles keep `generation << 32 | slot`; the slot is the table's local slot plus the table's base (sum of the lower
tables' capacities). Table 0's base is 0, so single-table handles are unchanged and the generation range is not
reduced. A handle's table is a function of its slot; a table-qualified call rejects a handle of another table with
`SU_E_STALE_HANDLE`. Input records stay version 1: world slots are table-disjoint, so the existing `(slot, field)`
canonical order is already table-grouped.

## Tests

`host_tables` / `host_tables_dll` (163 checks each):

- a two-kind world (ships `demo.actor`, pool `demo.pool`) with spawn and despawn in both tables, per-table
  capacities/bases/schema IDs, table-qualified reads, lowest-slot reuse with a bumped generation;
- cross-table handle validation: `su_host_despawn_in` with the other table's handle is `SU_E_STALE_HANDLE`;
  `su_host_despawn` routes by handle; a despawned handle is stale in its own table and in the other;
  `su_host_table_of_handle` still reports the table of a dead slot;
- one input record writing both tables (canonical order by world slot), encode round trip, duplicate-cell,
  unknown-field and out-of-range-handle refusals, and a write to an entity that dies before its tick failing the
  tick with the committed root unchanged;
- snapshot: version 3 for a multi-table world, digest before/after a restore identical, in-place restore
  identical, queued inputs kept and replayed;
- replay: record 6 ticks with inputs in both tables (keyframes every 2, digests every tick), open, play a fresh
  world to the end (final digest matches), seek to tick 3;
- memory accounting at 10,000 ships + 200,000 pool rows against one union table (see below);
- refusals: tables on a single-table descriptor, a table without a declared schema, `capsule_table` out of range,
  a capsule whose schema is not its table's, IR entity operations, more than `SU_HOST_MAX_TABLES` tables;
- a 1,000-row table with no system: the world steps, the idle table keeps the world tick, spawn/despawn in it
  work, and its canonical state restores;
- no allocation in a tick: on the static Linux build (malloc/calloc/realloc wrapped), a tick that applies a
  record touching both tables and runs both tables' systems allocates nothing, and neither does a failing tick
  that must undo it;
- descriptor versioning: the previous release's 96-byte `SuHostWorldDesc` is still a valid single-table world
  with the same identity as the 120-byte one, and a size that ends inside a field is refused.

### Byte identity against the parent revision

A small program (`ident`, built against each tree's headers and static libraries) creates two example worlds
(`examples/movement` at 3 ticks; `tests/fixtures/entities/despawn_move` at 5 ticks), prints the world identity,
the tick, `su_host_digest`, the snapshot size and `su_host_digest_fast`. Parent revision (`origin/main`, built in
`build-main`) and this branch print identical values:

```
examples/movement.capsule.json identity=9c7187e2...4511d tick=3 digest=51b56e93...4baee3 size=281 fast=33108689d7577df0
tests/fixtures/entities/despawn_move... identity=ad225710...1f73 tick=5 digest=4af1034d...290858 size=344 fast=3ad957224718b337
```

That is identity, snapshot bytes (same size, and the digests are SHA-256 of the bytes), fast digest and replay
identity. The single-table snapshot stays version 1/2 with the released layout (the state length is the header's
last word); the multi-table version 3 is a separate branch.

### Memory accounting

`host_tables` at 10,000 ship rows (2 lanes) + 200,000 pool rows (2 lanes) against one union table (4 lanes) of
210,000 rows, `su_host_memory` totals:

```
two tables 8,623,348 bytes (ship 365,777 + pool 7,303,731 + input 921,920 + metadata 31,920)
one union table 11,982,954 bytes
```

1.39x less in all, 1.9x less in columns (420,000 cells against 840,000); entity tables and the input buffers are
the rest. The test asserts a quarter less and prints the numbers.

### Benchmark (the motivating case)

`build/bench_host_tables 2000 27500 400`, 5 runs, medians of the per-run medians (ns per tick, one core of an
Intel i7-14700K, Linux 7.2.9, GCC 16.2.1 -O3, load average 8.24 with other agents building on the 20-core machine;
observations, not qualification):

| configuration | ns/tick |
|---|---|
| ships only (2,000 rows, 1 table, 1 system) | 27,879 |
| ships + idle 27,500-row table (2 tables, ship system only) | 27,552 |
| ships + pool table with one pool system (2 tables) | 104,050 |
| one union table (29,500 rows, 4 lanes, both systems) | 182,263 |

The ship-only system pays nothing measurable for a large second table (27.6 us against 27.9 us, inside the noise),
which is the point: with per-table begin/commit/publish the 27,500 idle rows are never hashed or committed. The
union world pays 182 us for the same two systems; the two-table world pays 104 us, 1.75x less, consistent with the
issue's expected ~2x on the whole tick for a world where most systems touch only the small kind.

## Unrun or blocked

- Native tier: `SUTEKH_NATIVE=ON` is not built here (no native toolchain configured in this tree); the host paths do
  not change native kernels. The sanitizer suite ran with the native tier off, as its CI matrix does for the OFF leg.
- Windows/MSVC: not available here.
- A stateful registered operator in a table other than 0: the base plumbing is in place (`su_hstate_begin_run` /
  `su_hstate_commit` take the table base) and single-table worlds pass the operator-state suite with base 0, but
  no test schedules one in a later table in this slice.
