## Implemented

1. **Numeric profile `fixed_q32_v1`** (`docs/NUMERIC_FIXED_Q32.md`: decision record and normative semantics;
   `src/ir/su_num.c`). Q32.32 in i64 chosen over Q16.16 (range), Q48.16 (16 fractional bits too coarse for unit
   quaternions and per-tick angular increments) and strict IEEE f64 (determinism traps: contraction, MXCSR state,
   x87, NaN payloads, libm). q32: saturating, round-half-even, exact wide sums for dot/cross/length, correctly
   rounded sqrt, rsqrt = div(1, sqrt); i32/i64: wrapping; division by zero, shifts and conversions defined.
   Integer-only C17 with 64-bit limbs.
2. **IR 0.3** (`LIVE_IR_SPEC.md` "IR 0.3"; `src/ir/su_ops03.c` operand table shared by verifier, VM and hash).
   Field types u32/i32/i64/q32; 64-bit fields are two u32 lanes `I` (`<name>.lo`) and `I+1` (`<name>.hi`), so
   world storage, canonical state, snapshots and migration are unchanged. Registers bool/u32/i32/i64/q32/v3/quat.
   93 operations: constants (`const_q32` num/den, exact RNE), typed loads/stores, `load_v3`/`store_v3`, bool ops,
   15-op families per scalar type (add sub mul div neg abs min max clamp eq lt le select shl shr), sqrt/rsqrt,
   conversions, vec3 (add sub scale neg dot cross len len_sq normalize clamp_len get make select), quaternion (make
   get mul conj rotate normalize integrate select). Semantic hash artifact format 3. The schedule union and candidate
   checks compare value types. Native backend refuses 0.3 (`ir_0_3_not_lowered`).
3. **space3d** (`docs/SPACE3D.md`; `profiles/space3d/native`). Host operator `space3d.query` (`space3d_ops_v1`,
   registered in `host_registry.c`): sort-and-sweep broadphase (axis of largest spread, order (min, slot), 32
   candidates per mover, 2^22 pair budget, flags), swept sphere vs sphere / mover / oriented box / capsule, and
   segment vs oriented finite gate (rectangle, disc, **ellipse** with semi-axes in the gate frame), with direction and
   fractional toi. Per mover: 2 contacts ordered by (toi, slot), counts, truncation flags, gate crossing. Host
   declarations gained typed lanes (`SuHostField.type` may be I32/I64/Q32); u32-only descriptors keep `rts_ops_v<N>`,
   `u32_mod_v1` and byte-identical digests.
4. **6dof_racer_microcosm** (`bench/space3d`, `capsules/space3d_racer`). Generated 41 km Bezier course, 16 elliptical
   gates, 48 seeded obstacles, N racers; two IR 0.3 systems (`racer.move`, 206 instructions: contact response, pace
   target, steering, quaternion integration; `racer.race`: gates, laps, counters, `emit_event`) plus the host query,
   run by `su_sched_run_ticks` with the entity runtime. Replay from scratch and from a canonical checkpoint;
   `expected.json` pins the N = 8, 720-tick digests.
5. **Host API typed helpers** (`include/sutekh/host.h`, additive): `su_host_field_value_type`, `su_host_read_i64`,
   `su_host_input_push_i64`.

## Not run / open

- Native backend tests (`test_native_scalar` gained a 0.3 refusal case): AsmJit is not vendored on this machine;
  only `su_native.c` was syntax-checked. Unrun.
- The control-plane path with a `space3d.query` world (`world.create` with `host_operator`) is not exercised by a
  test; the bench uses the same schedule executor in process. Snapshot JSON round trip of typed lanes works because
  lanes are u32 fields, but no test covers a 0.3 world through `world.snapshot`/`world.restore`.
- Migrations over typed lanes (add/rename/transform) are untested and unsupported in the spec.
- No trigonometry (not needed by the workload; quaternion integration is first order plus normalize).
- Accuracy domain of space3d: pairs within about 16 km, extents within about 4 km (results stay deterministic beyond).
- MSVC under the repository's `/W4 /WX` fails on pre-existing code (warnings C4267, C4701, C4702; C11 atomics need
  `/experimental:c11atomics`); not fixed here.

## Contract changes the integrator and other streams must know

- `include/sutekh/ir.h`: new opcode numbers 32..231 and types 3..7 (additive; SuInsn unchanged).
- `SuLirField` gained `value_type` and `lane` (appended); `SU_LIR_VALUE_TYPE()` reads 0 as u32.
- `SuSchedField` gained `value_type`; union and candidate checks reject value-type disagreements.
- `SuHostField.type` may be an IR 0.3 value type; host records of typed descriptors use operator
  `<schema_id>_ops_v<N>`, profile `fixed_q32_v1`, and lane type names. `schemas/capsule.schema.json` and
  `schemas/lir.schema.json` accept IR 0.3.
- Host API: the 32-bit cell API is unchanged; typed access to i64/q32 fields goes through the three new helpers.
  A host that wants q32 world fixtures writes both lanes as u32 cells (`<name>.lo`, `<name>.hi`).
- Build: all targets of this stream are in `cmake/SutekhNumeric3D.cmake` (one include line after the vm test). A
  deferred hook adds the IR 0.3 sources to `su_ir_oom_objs` and links `su_space3d` into the su_agent libraries.
- `PACK_VALIDATION.json`: regenerate (`tools/validate_pack.py --write-report`) on every merge instead of merging
  the counts.

## Recommended next steps

1. Control-plane test: a 0.3 capsule plus `space3d.query` through `sutekh serve` (world.create, step, snapshot,
   restore), on both platforms.
2. Native lowering of the i32/i64/q32 scalar families (straight integer code; differential against the VM), then
   vectors.
3. VM throughput: the movement system dominates (about 2.5 us per row at N = 256); candidates are a 0.3 fast path in
   the dispatch loop and skipping non-mover rows by a declared row filter.
4. Prediction/reconciliation support for the downstream workload: per-entity rollback from `su_host` snapshots and
   input records already works; measure resimulation cost of K ticks at N = 256.
5. Decide whether space3d's field IDs become a schema-relative binding (today the operator binds fixed IDs).
