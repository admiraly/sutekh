# M2-00b handoff: structural-command buffers, canonical merge, apply/commit, bounded event log

Adapted to contract r2 (deltas from the coordinator): rejected commands emit `SU_EVENT_REJECTED` and consume an `event_seq` and the per-tick event cap; successful despawns emit `SU_EVENT_DESPAWNED` (a = slot, b = old generation); no spawn queue (`SU_STRUCT_SPAWN` reserved, no callback); buffer entries = `min(chunk_size * per_row_cap, per_tick_cap)`; `events.read` reports `skipped` and `dropped`; config defaults 65,536 / 4,096 / 4,096.

## API summary

- `su_cmdq_create(nsystems, nslots, chunk_slots, per_row_struct_cap, per_row_event_cap, per_tick_struct_cap, per_tick_event_cap, &q)`: all storage allocated here. Chunk `c` holds `min(size_c, chunk_slots)` slots; the last chunk may be short.
- `su_cmdq_append_struct / append_event(q, sys, chunk, slot, ...)`: lock-free for disjoint `(sys, chunk)`; shared state is three atomics and a sticky overflow flag. Overflow (per-row, buffer or per-tick cap) writes nothing and returns `SU_E_RESOURCE_LIMIT`.
- `su_cmdq_reset`, `su_cmdq_overflowed`, `su_cmdq_counts` (quiescent writers only).
- `su_cmdq_merge(q, &view)`: verifies each buffer is strictly ordered by `(slot, seq)`. If all are, a binary-heap k-way merge; otherwise a stable merge sort of the concatenation, reported via `*_fallback` and `*_unsorted_buffers`.
- `su_cmdq_apply(cmds, n, &cb, tick, rec, rec_cap)`: exactly one record per command: `SU_EVENT_DESPAWNED` or `SU_EVENT_REJECTED` (a = struct kind, b = status). Unknown kinds reject with `SU_E_INVALID_ARGUMENT`.
- `su_cmdq_commit(q, &cb, tick, log, &rep)`: merge, then check `system_events + commands <= per_tick_event_cap` before any callback, then apply, combine by `(system, slot, seq, source)` with system events first on ties, assign `tick` and `event_seq` from the log's next seq, append. On a pre-apply refusal nothing runs and the log is unchanged.
- Event log: `su_evlog_create(capacity, base_seq)`, `append` (requires contiguous `event_seq`, evicts oldest, counts `dropped`), `read(cursor, max, out, &n, &next, &skipped, &dropped)`, `dump` (44-byte header `SUEL` v1 + 40 bytes per event, little-endian), `parse` (strict), `equal`.

## Ambiguities and decisions for the contract owner

1. **Worktree `include/sutekh/entities.h` predates r2.** `SU_EVENT_REJECTED` and `SU_EVENT_DESPAWNED` are defined in `su_cmdq.h` under `#ifndef` guards with the r2 values (`0xFFFFFFFF`, `0xFFFFFFFD`). Once r2 lands, the guards are no-ops. I did not add `SU_EVENT_SPAWNED`, `SU_SYSTEM_INDEX_HOST`, or `SU_EVENT_KIND_RESERVED_MIN` (unused here).
2. **Signature change.** `su_cmdq_create` takes `nslots` and `chunk_slots` instead of `nchunks`, because r2 defines buffer capacity from the chunk's slot count, including the short last chunk. `chunk_slots` may exceed `nslots` (a single short chunk).
3. **Despawn callback returns old generation.** `despawn(ctx, handle, &old_gen)`. The event's `a` is `SU_ENTITY_SLOT(handle)` (the target's slot), not the emitting row's slot. r2 says "a = slot", which I read as the target slot.
4. **No spawn callback.** Per r2, spawn is not queued, so `apply` has no spawn path. A `SU_STRUCT_SPAWN` command is rejected with `SU_E_INVALID_ARGUMENT`.
5. **Event cap precheck.** The per-tick event cap is checked against system events plus one record per command before any callback, so an over-cap tick changes nothing. r2 does not say whether the check is pre- or post-apply. Post-apply would need a rollback of the table.
6. **Per-row seq and reappearing slots.** Rows are runs of the same slot in one buffer. If a slot reappears non-consecutively, its row restarts at seq 0. Merge detects the out-of-order buffer and stable-sorts, so output stays deterministic. The contract should say whether rows must be contiguous.
7. **Reads.** `cursor > next_seq` is `SU_E_INVALID_ARGUMENT`, which r2 does not cover. `skipped` is `oldest - cursor` when the cursor is behind. `events.read` then needs `max <= 256` at the control-plane layer, which is outside this file.
8. **Log bounds.** `base_seq` is capped at 2^62 to keep arithmetic safe, and capacity at 1,048,576 (`event_log_max` validation is 1..1,048,576, consistent with r2 caps). Event sequence wrap is not modelled.
9. **Merge cost** is O(N log B) with B = systems x chunks. The heap is preallocated. No speed claim is made.
10. **`su_cmdq_counts`** sums stored records and is valid only after writers join.
11. **`fill`** (first-write rank) is diagnostic only and not used for ordering. It exists so the M1 mutant can be checked.
