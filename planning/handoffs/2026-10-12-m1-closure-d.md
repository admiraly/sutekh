## What changed (behaviour)

1. **Network bypass closed (audit blocker 1).** The network filter (`build_socket_filter`) now also returns EPERM for
   `io_uring_setup` (425), `io_uring_enter` (426) and `io_uring_register` (427), so IORING_OP_SOCKET cannot open a socket.
   It also denies, with EPERM: ptrace 101, process_vm_readv 310, process_vm_writev 311, kcmp 312, keyctl 250, add_key 248,
   request_key 249, bpf 321, perf_event_open 298, userfaultfd 323, pivot_root 155, chroot 161, mount 165, umount2 166,
   unshare 272, setns 308, open_by_handle_at 304, name_to_handle_at 303, kexec_load 246, init_module 175, finit_module 313,
   delete_module 176, reboot 169, swapon 167, swapoff 168, acct 163. Not denied: mmap, mprotect, personality.
   Wrong architecture and x32 (nr >= 0x40000000) still kill.
2. **Worker self-sandbox (both roles).** `src/agent/su_sandbox.c`: installed in `su_worker_main_with_hooks` after startup.
   execve 59, execveat 322, fork 57, vfork 58: EPERM. clone 56: EPERM unless CLONE_THREAD (flags read from args[0]).
   clone3 435: ENOSYS, so glibc falls back to clone. Verified before serving: execve("/nonexistent/...") must return EPERM.
   State in `internal.stats` as `self_sandbox` (`on`, `opted_out`, `unavailable`) and as `Seccomp_filters: 2` in /proc.
   `SUTEKH_WORKER_SANDBOX=0` is honoured only when the build is ASan or TSan.
3. **Filesystem writes (disposable children).** Landlock (raw syscalls): every write-class access handled, none granted;
   reads not handled. Applied in the child before exec, outcome reported in the wire record. Containment object:
   `fs_write_denied` ("landlock" or "none"), `fs_abi`, `fs_reason`. The active worker keeps write access ("none").
   `SuProcLimits.writable_dir` is a test seam only (NULL in production).
4. **Digest guard.** `digest_matches` calls `su_agent_digest_fields_match` (exported) so each field can be tested.

## Deviations (stated plainly)

- **Landlock is applied before exec in the disposable child, not after startup.** The write denial then survives exec, and
  the child verifies the outcome before reporting. The write denial is also checked from inside the worker by the
  `internal.test.fs` probe (EACCES in the project root and `/tmp`).
- **Self-sandbox verification uses execve of a missing path.** Under the filter the verdict is EPERM (decided before path
  lookup); without it ENOENT. Running `execve("/bin/true")` as the verification would replace the process. The seam
  test (`internal.test.sandbox`) does try `execve("/bin/true")` and `fork()` and reports EPERM for both.
- **Arch and x32 checks run in child mode** (`test_containment --child <kind>`), so the network filter is tested alone; the
  worker self-sandbox also kills foreign arches, which would hide a mutant of the network filter if the worker were used.
- **Sanitizer lane uses `detect_leaks=0`.** LeakSanitizer attaches with ptrace, which the network filter denies, so the
  `control` test fails on leak reporting in a worker child (verified: passes with `detect_leaks=0`, fails without). The
  self-sandbox is ON in the ASan lane (`containment` checks `on`); `SUTEKH_WORKER_SANDBOX=0` was not needed and not used.
  Leak checking is therefore not part of this lane's evidence.
- **The digest mutants target `su_agent_digest_fields_match`**, not the old `digest_matches` body, which now calls it.
- **`fork` denial is redundant on glibc** (glibc `fork()` uses `clone` without CLONE_THREAD, which is denied by the clone
  rule). The `fork` entry is kept as documentation of intent; it is not what stops glibc fork.
- **x32 positive control is unavailable on this host**: the unfiltered x32 socket returns ENOSYS here. The x32 kill itself
  is tested (SIGSYS), and the mutant M-X32 is killed through the child's exit status.
- **Landlock is not an active-worker control**: the active worker reports `fs_write_denied: none`, with the reason.
