## 1. Item 1 (per-row order bug): fixed

`su_cmdq_append_struct` and `su_cmdq_append_event` take the VM-supplied per-row `seq` (one counter per row
shared by `despawn_self` and `emit_event`). Within a buffer the seq must strictly increase for the current row,
else `SU_E_INVALID_ARGUMENT` with no state change. Per-kind caps are still counted per kind. The runtime
emitter passes the VM seq through. `test_cmdq` gains a despawn-then-emit and an emit-then-despawn order test
and a duplicate-seq rejection. The tick oracle now encodes despawn seq 0, event seq 1 (the fixture's order);
the "known deviation" comment is removed.

## 8. Deviations (report to owners)

1. Handles are JSON integers (u64, exact in the reader). Clients with double-precision numbers lose precision
   above 2^53. Not switched to strings, because the reader is exact (documented in `docs/AGENT_RPC.md` section 15).
2. `events.read` `max` above 256 is `SU_E_TYPE` at the supervisor; the worker's `SU_E_RESOURCE_LIMIT` is not
   reachable through the supervisor.
3. `world.inspect` columns and `entity_ids` still page the fixture's initial rows (`row_count`); spawned rows
   are read with `entity`. Changing paging would change M0 semantics.
4. The C worker-level integration tests listed for `tests/entities` were not written as a separate C file.
   The same scenarios run through the real binary in harness TX7 and TX8, and the world-level churn, retirement
   and fault cases are C tests (`test_churn`, `test_entity_tick`). The retired slot is not produced through the
   control plane (no worker-level seam); it is covered at world level.
5. "Commands applied in append order" mutant is implemented as reversed canonical application. A raw
   append-order variant is equal to canonical under the current single-writer-per-buffer ordering and was not
   separately mutated.
6. The 1,000,000-row admission refusal is measured, not in the harness (generating and creating a 1M-row
   fixture would dominate TX7); the arithmetic is covered by `test_entity_tick` `test_budget`.
7. The benchmark's second run wrote its log but not its JSON (the first run's JSON is the older attempt).
   Numbers above come from the log.
8. The per-chunk buffer memory at 1M rows is 288 MB per entity system with caps 4. Reducing it needs an owner
   decision (contract B8 budget or per-row caps), not made here.
