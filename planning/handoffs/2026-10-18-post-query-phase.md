## What changed

1. **Post-query ordering** (`src/runtime/jobs/su_effects.c`): an IR system's `after` edge to a host operator of an
   earlier phase is admitted (all other cross-phase edges stay refused, with clearer messages). Execution is capsule
   order (unchanged), so the IR system runs after the operator in the same tick. Same code path for `sutekh serve`
   (worker.c) and `host.h` (su_host.c). Existing schedules are unaffected (the rule only accepts edges that were
   refused before).
2. **`space3d.query_prox`** (`profiles/space3d/native/space3d_ops.{c,h}`, record
   `profiles/space3d/space3d_query_prox.capsule.json`, registered in the worker registry and the host operator
   list): base lanes + `prox_margin` (q32 read, 66), `prox_slot` (68), `prox_gen` (69), `prox_dist` (q32, 70).
   Constants hash 79204fc06c5d7d1e5a0ca2e85a687f234c731f6698538007b81eecd9602d7a84. `space3d.query` is untouched
   (same descriptor, hash, code path with `prox = 0`).
3. **Diagnostics**: `su_sched_explain_mismatch` (schedule.h) names the two systems, IDs, names and value types of
   a field conflict and the q32/i64 lane rule; used by `world.create` and `su_host_world_create`.
   `su_effects_check_declared` now says the read/write flags must equal the IR's loads/stores and what to change.
   Rules documented in `docs/SPACE3D.md` section 2.
4. **Consumer build**: `SUTEKH_TOOLCHAIN_HOME` in `tools/env-windows.ps1`; `SUTEKH_PYTHON` is a cache variable
   (a consumer may preset it); `SUTEKH_VULKAN_INCLUDE_DIR` (cache, INTERNAL) and `Sutekh::vulkan_headers`
   (interface target, when headers were found and the renderer is on). README "Sutekh as a submodule".
5. **Example**: `examples/host_space3d` gains `arena_respond.*` and `arena_query_prox.capsule.json` (generated by
   `gen_arena.py`; the existing files are byte-identical) and `arena_host --respond [--coast] [--dump-fixture p]
   [--dump-final p]`.
