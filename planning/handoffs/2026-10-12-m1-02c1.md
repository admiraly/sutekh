## 2. Design (what changed)
- `world.specialize` is a supervisor operation. Three internal worker requests:
  - `internal.specialize.identity` (active worker, read-only): semantic hash, source/capsule hashes,
    layout generation, revision.
  - `internal.specialize.admit` (DISPOSABLE worker only): compile, then differential admission over the
    corpus (42 cases) and the system's own test cases (`<stem>.test.json`, 3 cases for movement), run
    natively. Answers `status: admitted|mismatch`, `artifact_hash`, `evidence`, `first_mismatch`.
  - `internal.specialize.install` (active worker): recompile (compilation only), require the admitted
    `artifact_hash`, recheck revision, semantic hash, layout generation; `su_nv_trust_admitted` marks the
    kernel admitted by hash; publish as before. The worker no longer runs admission.
  - The worker method `world.specialize` is removed from the dispatch table.
- Supervisor (`h_world_specialize`) spawns the disposable like `candidate.evaluate` (fresh child, RLIMIT_AS
  and CPU, wall timeout, `su_proc_kill` on timeout). `SuProc` now records how a failed child ended
  (`end_kind`, `exit_code`, `term_signal`); the failure `error.detail` carries it.
- `error.detail` is a new optional member on protocol errors (`su_proto_error_detail`).
- Fault seams: `su_nv_test_arm` and the env reads (`SU_TEST_FAULT`, `SU_TEST_FAULT_MS`) exist only under
  `SU_TEST_FAULT_HOOKS`, which only the test worker defines. Modes: wrong_kernel, wrong_world, crash, hang,
  delay (disposable); perturb_recompile (active install). The release binary has no such strings
  (`check_release_seams.py`, ctest `release_seams`; negative control verified).

## 4. Deviations
1. Admission in the disposable worker is the only place a candidate kernel runs. The active worker only
   compiles and compares the hash. Revert-design mutant (admission in active worker) not built.
2. Stale revision between admission and install is tested at worker level (world.step between admit and
   install) but not at supervisor level: the agent is synchronous and cannot interleave a second request
   during a call. The "install a new revision while admission is in flight" ordering is therefore not
   reproduced end to end.
3. `world.close` during admission: not reachable (same reason). The install path refuses a closed world
   (unknown world_id), which is the only observable effect.
4. Own test cases are run natively by the disposable kernel through the world fixture; the reported
   `evidence.rows_checked` counts corpus rows only.
5. The disposable's own-case failure reports one first mismatch (case name and reason), not a
   field/row/expected/actual tuple (the case runner compares whole columns).
