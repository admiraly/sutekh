## Design

- **The operator's records are the IR records.** `emit_event` appends a 40-byte `SuEvent` through the same commit and
  the same log as `emit_event` in IR: same kind range (below `SU_EVENT_KIND_RESERVED_MIN`), the operator's schedule
  position as `system_index`, and `seq` numbering its emissions in the run from 0. Nothing downstream (replay,
  presentation, audio) can tell the two apart, so digests, snapshots and replays cover the records with no new
  format: the log is already part of the canonical snapshot.
- **One serial call per run, so emission order is canonical.** An IR system needs (slot, seq) as its merge key only
  because it runs in parallel chunks; a host operator is called once, serially, so the order in which it calls
  `emit_event` is already deterministic. The engine therefore numbers `seq` itself (a run counter) and keeps the
  records in emission order: a tick's log is ordered by schedule position and then by the order each system produced
  its records. `slot` stays the row the event is about (checked against `rows`), so a per-entity stream keeps its
  entity without making the merge key reorder the records.
- **Over-cap is the IR path's outcome.** Past `max_events_per_tick` the append stores nothing and returns
  `SU_E_RESOURCE_LIMIT`; the refusal is sticky, so the tick fails in that system and nothing is committed also when
  the operator ignores the code (the IR queue's overflow flag works the same way). Reserved kinds (`SU_E_TYPE`) and
  out-of-range slots (`SU_E_INVALID_ARGUMENT`) are refused the same way. The world's own per-tick cap counts host
  records too, checked at the boundary before anything is appended.
- **Where the records live between run and commit.** The operator's buffer is in its per-world instance (allocated at
  world creation, `40 x max_events_per_tick` bytes, zeroed per call like the scratch); `run_host` drains it into the
  entity tick's merge buffer (`40 x the sum of the declared caps`, allocated when the entity cache is built, not per
  record), which numbers each record by schedule entry; the boundary merges the three sources. No allocation in a
  tick (tested with wrapped malloc/calloc/realloc).
- **Versioning.** Both additions are appended: `SuHostOperatorRun` after `state` (an operator built against the
  shorter struct still runs; tested with a local copy of that layout), and `SuHostOperatorDesc` after
  `state_reserved` (a version 2 descriptor still registers and gets `emit_event == NULL`). A nonzero cap joins the
  semantic hash, so a snapshot or replay recorded with one cap is refused in a process that registers another; an
  operator without events keeps the identity, snapshots, digests and replays of earlier releases (the whole suite,
  including the pinned digests, is unchanged).

## Review fixes (round 2, adversarial review nits)

- **Event label hash (format pin, before merge).** `reg_identity` hashed 21 bytes of `"sutekh.host.events.v1"`, which
  excludes the trailing NUL, while the other two labels hash theirs. It now hashes the literal including its NUL, and
  all three lengths come from `sizeof` of the literal so they cannot drift. Only worlds with a nonzero declared cap
  are affected (new in this PR); cap-0 and version 2 worlds keep byte-identical identities and digests, re-checked
  against `a4cab99` (below).
- `src/world/entities/su_cmdq.h`: the `su_cmdq_commit_with_events` comment had the roles reversed; it now says the
  operator supplies kind, slot and payloads and the engine fills `system_index`, `seq`, `tick` and `event_seq`.
- `include/sutekh/host.h`: the memory bullet claimed the entity tick's merge buffer is allocated once with the world's
  other buffers; it is 40 bytes times the sum of the declared caps, allocated lazily when the entity cache is built
  (the first step) and rebuilt when the cache is invalidated. The operator's own buffer is still allocated at world
  creation.
- `include/sutekh/host.h`: `emit_event`/`emit_ctx` are documented as valid only for the duration of that `run` call;
  calling them after it returns, or once the world is destroyed, is undefined.
- `cmake/SutekhHostOps.cmake`: `host_events_verify_cap_dll` is registered too, so the PR's "verify cap (static+DLL)"
  claim is true (it was static only).
- `include/sutekh/host.h`: `SU_HOST_OPERATOR_RUN_EVENTS_SIZE` pins the 2026-10-27 run layout (through `emit_ctx`),
  next to `SU_HOST_OPERATOR_RUN_STATE_SIZE`; `tests/host/test_host_events.c` static-asserts both layouts. `test_cap`'s
  `check_unchanged` also compares the canonical snapshot bytes of the refused tick with the last committed one.

## Unrun or not covered

- Windows/MSVC build and the Windows clang CI lane: not run here (no Windows environment).
- `SUTEKH_NATIVE=ON` builds: not run here (the native backend needs the AsmJit bootstrap); the new code is on the
  host-operator path and does not touch native lowering, but CI covers it.
- The out-of-process control plane (`sutekh serve`, the worker): not affected by design (registered operators do not
  exist there); not re-run beyond the existing suite.
- A chunked (`#142`) host operator's event ordering: the plan is that the engine merges chunks in canonical chunk
  order, so a chunked operator's records stay deterministic; not implemented or tested, because chunked host
  operators are not implemented.
