## Behavior and design notes
- `su_vm_context_create(module, layout_generation, &ctx)` binds one verified module and one layout generation. The module is borrowed and must outlive the context.
- Wrapper ordering: envelope and counts (INVALID) -> per-binding shape (INVALID) -> generation, field ID and row count (SCHEMA) -> row limit (RESOURCE_LIMIT) -> aliasing (INVALID). Input and output bindings are matched by field_id; duplicates or unknown IDs are SCHEMA.
- Registers carry a type tag (u32 or bool). Operand reads check the tag and return SU_E_INTERNAL on mismatch. Store-once per row is checked at run time and returns SU_E_INTERNAL.
- `su_vm_run_system` selects the module's declared fields from the world's views (so a world with extra fields still works), returns SU_E_SCHEMA_MISMATCH if a declared field is missing, and commits the module's writable fields via `su_world_commit_staging` only on SU_OK. It does not begin, publish or abort the tick.
- Failed instruction index: `su_vm_context_last_failed_insn(ctx)` and `outputs->failed_insn`.

## Contradictions and gaps with fixtures and contract
- `SuLirModule` (su_lir.h) carries no `layout_generation`. The contract requires a layout-generation check, so the VM takes it as an argument to `su_vm_context_create`. The caller must take it from the capsule's `schema.layout_generation`. Suggest adding the field to `SuLirModule` (owner: M0-02) so the value is not duplicated.
- Contract section 3 lists aliasing before the row limit. Implemented as row limit before aliasing, because the aliasing byte-range computation needs `row_count` bounded first. Same status codes; differs only when several faults are present at once.
- Fixture `t03/*` each has one case; `t02` has two per file. No fixture covers row limit, aliasing or generation; those are tested in code only.
- Fixture world files list columns by name only. The loader requires every module field to have a column of the right length.
