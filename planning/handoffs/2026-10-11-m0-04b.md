## T04 negative matrix (14 cases: 8 pass, 6 FAILED)
Passing: all 7 in `examples/negative_cases.json` (including `duplicate_key`, which goes through the engine as raw bytes; the harness never parses the `.lir.json`), and `tests/fixtures/invalid/denied_read.lir.json`.

FAILED (6), all `tests/fixtures/invalid/*.lir.json` with capsule `tests/fixtures/invalid/movement.capsule.json`. Expected vs actual:
- too_many_instructions: SU_E_RESOURCE_LIMIT vs SU_E_IO
- nested_depth_33: SU_E_RESOURCE_LIMIT vs SU_E_IO
- store_same_field_twice: SU_E_UNDECLARED_WRITE vs SU_E_IO
- bool_as_u32: SU_E_TYPE vs SU_E_IO
- fractional_constant: SU_E_TYPE vs SU_E_IO
- constant_4294967296: SU_E_TYPE vs SU_E_IO

Classification: ENGINE BUG, not a fixture error. Evidence: `src/agent/su_agent.c` `locate_capsule` (around line 237) always resolves the capsule's own `source` (`movement.lir.json`) with `su_path_sibling` before `h_capsule_submit` applies `source_path`. `tests/fixtures/invalid/` has no `movement.lir.json`, so the call fails with SU_E_IO ("capsule source path rejected by the project path policy") before the override is used. The same failure happens for any override when the capsule's own sibling is missing. The 8 passing cases sit in directories whose capsule source exists, which is consistent with this. Expected fix: skip the capsule's own sibling resolution when `source_path` is given (the override replaces that binding). Not hidden: the harness was not changed to add a `movement.lir.json` copy.

The expected code for `store_same_field_twice` (SU_E_UNDECLARED_WRITE) is still the fixture's judgment call (its note says there is no dedicated code). It cannot be confirmed until the engine bug is fixed.
