# Issue 140, slice 2: a table-aware entity tick, cross-table space3d, stateful operators in any table

Branch `multi-table-slice2`, based on `origin/main` (7f2b431, the merged slice 1). Slice 1 built the container
(per-table storage, handles, identity, snapshot version 3, input routing); this slice makes the entity tick,
events and the space3d operator table-aware, and lifts the creation refusals. Design note:
`docs/MULTI_TABLE_WORLDS.md` (sections 3, 4, 5, 8).

## What changed

- `src/runtime/entity_tick.c/.h` — `su_ent_run_ticks_tables`: one command queue and one event log for the
  world, one entry per scheduled system with that system's own table, rows, layout generation and world-slot
  base, per-system chunk caches and entity views, per-table despawn routing at the boundary, per-table
  begin/zero/publish, an idle table kept at the world tick. `su_ent_run_ticks` is the `nw == 1` wrapper, so the
  single-table path is the released one. Event records carry world slots; the despawn callback maps a world
  handle to its table's local handle.
- `src/world/entities/su_cmdq.c/.h` — `SuCmdTables` / `su_cmdq_commit_tables`: per-table despawn callbacks and
  `slot += base[sys_table[system_index]]` on command and IR event records; `su_cmdq_commit_with_events` is the
  `t == NULL` path, byte for byte.
- `src/vm/su_vm.c/.h`, `src/vm/su_vm_plan.c/.h`, `src/ir/su_ops03.h` — `su_handle_live_base` and
  `su_vm_context_set_entity_table_base`: `handle_live` takes a world slot of the system's own table.
  `slot_u32`, `gen_u32`, `despawn_self` and `emit_event` already used `base_slot`; the entity tick now sets it.
- `src/runtime/schedule.c/.h` — per-entry target set (`su_sched_set_host_target`), `run_host` fills the target
  columns/views from the target world and calls `run_targets`; native and chunked kernels use
  `s->tables[e->table].layout_generation` (slice-1 nit a); `su_sched_run_ticks_tables` routes entity/event
  systems to the table-aware entity tick.
- `src/world/su_world.c/.h` — `su_world_build_read_invocation`: a target table's read views from working columns
  during its tick, committed columns when it has no system (a table with no system is never begun).
- `src/host/su_host.c` — removes the slice-1 refusals (IR entity operations, operator events); target-table
  creation checks and `bind_target` (target lanes by name and value type against the target's declared schema,
  readable in the target world, binding folded into the identity); `su_host_memory` now counts queued input
  records and the in-place restore scratch, and its `total` includes them.
- `src/host/su_host_registered.c` — registered operators with a target set (`target_fields`, `run_targets`,
  `run->target_*`); the instance is sized for its own table plus the target table, and `run.rows` is the
  operator's own table's row count; `run->table_base`.
- `src/host/su_host_state.c/.h` — the DROP_DEAD purge validates each key against the committed entity table of
  the table its slot belongs to (`SuHStateTables`), so an entry keyed by another table's live handle survives; a
  multi-table stateful operator purges at every publish (its own views cannot validate another table's key).
- `src/runtime/rts/host_decl.c`, `profiles/space3d/native/space3d_ops.c` — target-set descriptor validation and
  the eight cross-table `space3d` run forms (v1 sweep and v2 grid, base/prox/shape/compound). Single-table
  forms are untouched.
- `include/sutekh/host.h` — world descriptor version 5 (`capsule_target_table`), operator descriptor version 4
  (`target_field_count/target_fields`), `SuHostOperatorRun.target_*`, `SuHostOperatorRun.table_base`,
  `SU_HOST_TABLE_NONE`, `SuHostMemory.queued_inputs/restore_scratch`, the one world-slot rule, the per-table
  schema digest in the identity formula, and a "cross-table host operators" section.
- `docs/MULTI_TABLE_WORLDS.md`, `docs/SPACE3D.md`, `docs/IMPLEMENTATION_STATUS.md` — the slice-2 design,
  formats, the slot rule, the cross-table form and its limits.
- Slice-1 nits: (a) native kernels use the entry's table layout generation; (b) the identity formula now shows
  the per-table schema digest (the code already folded it); (c) `su_host_memory` counts the categories it
  claimed to; (d) no IR `spawn` op is listed; (e) the slice-1 handoff says world descriptor version 4;
  (f) `test_large_idle_table` compares the small table's columns and the allocation test covers a failure
  inside a system run (an over-cap `emit_event`).
- Tests: `tests/host/test_host_tables_entities.c` (new in this slice), `tests/host/test_host_tables.c`
  (updated), `tests/space3d/test_space3d_bind.c` (temp files under `TMPDIR`), `CMakeLists.txt` (the two new
  test targets). The stray `bound_*.capsule.json` / `unbound_other_schema.capsule.json` files at the repository
  root are removed.

## What the tests cover

`host_tables_entities` / `host_tables_entities_dll` (198 / 186 checks):

- the issue's end-to-end world: ships in table 0 (move, emit an event, despawn themselves), projectiles in
  table 1 (spawned by the host, moved and despawned by IR, collided against the ships by a cross-table
  `space3d.query`); 12 ticks with spawns, events and despawns in both tables; events in schedule order with
  world slots; snapshot (version 3) restore, in-place restore, and a replay round trip;
- world-slot semantics in table 1: `slot_u32` is the world slot, `gen_u32` the row's generation, `handle_live`
  answers from the system's own table (another table's slot is not live);
- a target table with **no system**, for the v1 and v2 query forms: the committed-read fallback, a contact that
  names the target's world slot and generation, and a tick that allocates nothing;
- a registered operator with a target set in table 1 reading table 0's working column: `run.rows` is its own
  table, `target_rows` the target's, both bases, the alive view and the column values;
- operator events in a multi-table world (a table-1 operator's records join table 0's IR records in schedule
  order, with world slots);
- a stateful registered operator in table 1 with `SU_HOST_STATE_DROP_DEAD`: entries keyed by table 0's live
  handles survive, entries whose handle died in either table are purged;
- descriptor sizes: v4 and v5 describe the same world when no target is set, and a v4 descriptor does not read
  `capsule_target_table`;
- refusals: a target set on a single-table descriptor, an out-of-range or same-table target, an IR system that
  names a target, a missing target lane;
- no allocation in a tick: the two-table entity tick, a failing operator run, and a cross-table query.

`host_tables` / `host_tables_dll` (197 / 177 checks) additionally: an IR entity system runs in a multi-table
world (the slice-1 refusal is now a positive test), the small table's columns are equal with and without an
idle second table, memory categories (queued input records, restore scratch, the v1 caller), and the
allocation test's system-run failure.

## Byte identity for single-table worlds

All comparisons below were made by building the same probe against `origin/main` and this branch (each tree's
headers and static libraries) and diffing the output.

`ident` creates seven single-table worlds from committed capsules and fixtures (movement 3 ticks, despawn_move
5, emit_then_despawn 3, const_store 3, guard 3, plus movement and despawn_move with the previous release's
96-byte descriptor) and prints identity, tick, `su_host_digest` (the SHA-256 of the snapshot bytes), snapshot
size and `su_host_digest_fast`. The two outputs are **identical**:

```

despawn_move  identity=97ccf1a5...5bb531 tick=5 digest=fbed6593...911f25 size=344 fast=5159f2faa4986fd4
emit_then     identity=a18c1e9a...d2f642 tick=3 digest=724a3155...98b3af size=344 fast=08f6ad1dc97d93e2
const_store   identity=394a63fe...6e072b tick=3 digest=69444955...36309d size=244 fast=31ea83ee0b0f1bb1
guard         identity=ba2f4d6a...18a89a tick=3 digest=b3519839...7e35fa size=344 fast=41d68645fa92d117
```

The determinism matrix (`det_matrix`, tiers `reference`, `planned`, `mixed`, 219 manifest lines each including
replay digests) was run against the same generated fixtures on both trees: the three manifests are
**byte-identical**. The full suite's golden replays, scenario and RTS digests pass unchanged on both.

Slice-1 multi-table snapshots and replays stay valid: a two-table world (const_store in table 0, movement in
table 1) built against `origin/main` writes a snapshot (428 bytes) and a replay (1743 bytes); the branch creates
the same world, and both files are **byte-identical** and restore/play to the same digest (identity
`6b60e621...ece0d1`, digest `bd1c8c89...0da495d`). So no snapshot version bump was needed: slice-1 multi-table
identities and formats are unchanged (the `SUHTARGET` section appears only for a capsule that binds a target
set).

Every host test's stdout was compared between the two trees (verbose ctest logs, paths and timings normalised):
identical except `host_tables`/`host_tables_dll`'s memory numbers (the schedule entry grew by the target-set
fields, so `metadata` is 3,600 bytes larger; not part of identity, digests or snapshots) and its check counts,
and one timing benchmark (`host_events_verify_cap_dll`).

## Item 6: in-tick spawning by a host operator

Not implemented; documented in `docs/MULTI_TABLE_WORLDS.md` section 8.3. The structural command queue carries
despawns only (`SU_STRUCT_SPAWN` is reserved and has no producer); a spawn needs a per-table free-slot
allocation at the boundary, a canonical order against the tick's other structural commands, and a value payload
that does not fit the current 32-byte command record. That is a command-queue format change, not a flag, so it
is left out rather than half-defined. Host `su_host_spawn_in` between ticks works in every table.

## Unrun or blocked

- Native tier: `-DSUTEKH_NATIVE=ON` needs the pinned AsmJit bootstrap, which is not present in this checkout;
  the native path is unchanged except the layout-generation argument (slice-1 nit a). The ASan leg runs with the
  native tier off, as its CI matrix does.
- Windows/MSVC: not available here.
- The effect analysis does not model a cross-table operator's target reads; the host tick is serial and
  schedule-ordered, so results are deterministic, but a future parallel tick would need the target reads as
  conflicts (documented).
- A target row is static for `space3d` (the target set has no previous position); a moving target is tested at
  its end position (documented).
