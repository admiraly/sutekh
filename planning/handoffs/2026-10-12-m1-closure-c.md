## Behaviour delivered

- **Containment (C07).** Children get RLIMIT_AS 4 GiB, RLIMIT_FSIZE 256 MiB (SIGXFSZ ignored, so writes fail with EFBIG), RLIMIT_CORE 0 and network denial. The active worker has RLIMIT_NOFILE 1024 and no CPU bound. A disposable worker has RLIMIT_NOFILE 64 and its CPU bound. Network denial is a hand-written seccomp-bpf filter on x86-64 (PR_SET_NO_NEW_PRIVS, then socket, connect, accept, bind, listen, accept4 and socketpair return EPERM; socket is verified in the child before exec). Off x86-64 or on failure it falls back to unshare(CLONE_NEWNET). The child reports read-back limits and the mode it verified through a close-on-exec status pipe. `candidate.evaluate` and the `world.specialize` answer carry a `containment` object.
- **Safe retirement.** The in-flight count is zero at every system boundary. Release from inside a kernel call defers unmapping until the call returns. The quarantine table compares whole hashes.
- **Chunked native kernels.** `su_nv_run_system_chunked` runs a native kernel over the canonical su_jobs chunks on sliced column views. It commits once, after all chunks succeed. The status is the lowest failing chunk's. Tick workers stay opt-in (default N=1). Decision recorded in docs/AGENT_RPC.md section 13: whether parallelism becomes the default is a product decision for M2.

## Test specifics

- `containment` (test_containment, 34 checks). Probe runs in a child spawned with the disposable limits and asserts socket EPERM, EFBIG after exactly 1 MiB, EMFILE at 64 descriptors, `Seccomp: 2`, and /proc/self/limits values. Control child shows unrestricted behaviour (8 MiB written, 256 open descriptors, `Seccomp: 0`). Under `SUTEKH_WORKER_AS_BYTES=0` the address-space check expects unlimited.
- `safe_retire` (test_safe_retire, 27 checks). In-flight count zero at each boundary of 3 native ticks. Release inside the call: state RETIRING, in flight 1, still mapped; result equals VM; freed after return. Quarantine key: a hash differing only in the last digit, or at digits 9 and 0, is not found.
- `native_chunked` (test_native_chunked, 87 checks). N in {1,2,4} x {VM, native scalar, native AVX2 when available}: 50 ticks on 100,001 rows and 3 ticks on 1,000,000 rows; final columns equal the serial VM; chunk seam calls equal ticks x chunks for N>1 and 0 for N=1. Failure injection on chunk 2: tick fails, committed columns unchanged, clean retry equals reference.
- Harness TX6 (22 checks, was 12): active worker RLIMIT_AS exactly 4 GiB, RLIMIT_FSIZE 256 MiB, RLIMIT_NOFILE 1024, no CPU limit, Seccomp 2; observed disposable child exactly 4 GiB, 256 MiB, 64 open files, Seccomp 2; candidate.evaluate containment object matches.

## M06 equivalence argument

`digest_matches` returns 0 only when the worker's revision string equals the expected one, the tick equals the expected tick, and (when given) the snapshot SHA-256 equals the expected one. Removing the tick comparison changes the outcome only if a digest has a matching revision and SHA but a different tick. The snapshot bytes encode the tick (SUWSTATE header, u64 tick; src/world/snapshot.c), so equal SHA implies equal tick. Both replay sites that decide a result (checkpoint restore and log replay in `su_agent.c`) compare the SHA, so the tick check there is implied. The quarantine-rollback site passes no SHA, but it ignores a mismatch (it only returns on worker death), so removing the check there changes nothing. M06 is therefore equivalent under the assumption that the snapshot SHA covers the tick. That assumption is argued from the snapshot format; it is not separately tested.
