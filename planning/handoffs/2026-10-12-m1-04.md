## What was built

1. **Partition and pool (`su_jobs.h/.c`).** `su_jobs_chunk_count`, `su_jobs_chunk_bounds`, `su_jobs_effective_chunk_rows`: boundaries depend only on row count and chunk size (auto size: at least 1024 rows, about 64 chunks), never on worker count. Pthread pool: `su_jobs_pool_create/run/destroy`. `order != NULL` gates completions so the physical completion sequence equals a given permutation (test hook). `su_jobs_seeded_permutation` is splitmix64 with Fisher-Yates.
2. **Chunked runner.** `su_jobs_run_system_chunked(w, mod, gen, opt, rep)`. Each chunk calls `su_vm_invoke_v1` on a per-worker context with sliced views (pointers advanced by `begin`, `row_count = len`). Per-chunk status array. The lowest failing chunk decides the reported status. Nothing is cancelled, so the lowest index is order-independent. Staging is committed (`su_world_commit_staging`) only when every chunk returned `SU_OK`. The test-only fault seam returns `SU_E_CANDIDATE_FAILED` for chosen chunks.
3. **Effect analysis and graph (`su_effects.h/.c`).** Effects are derived from IR LOAD/STORE. `su_effects_check_declared` requires declared READ/WRITE to equal derived effects. `su_effects_build` rejects duplicate IDs, unknown or cross-phase edges (`SU_E_INVALID_ARGUMENT`), declared-vs-IR mismatch (`SU_E_SCHEMA_MISMATCH`), ordering cycles (`SU_E_INVALID_ARGUMENT`, message `ordering cycle: a -> b -> ... -> a`), and write/write or read/write conflicts between systems declared parallel in the same phase with no ordering path, direct or transitive (`SU_E_SCHEMA_MISMATCH`, message names the pair and field). Canonical serial order: phases by strcmp, then Kahn by (priority, system_id).

## Unrun checks and caveats

- The CMake build, CTest, and the project's dev/release presets were not run; CMakeLists.txt was not edited.

- The bench is one machine, n = 7, shared host. It is not a qualification.
