## 2. Design
- Records: per world, the native kernel installed per system (`NatRec`: artifact_hash, requested backend,
  tier). Cleared by candidate.install, world.restore, world.close.
- Attribution: a worker death during world.step on a world with installed kernels quarantines every kernel of
  that world (conservative: the crashing kernel is not identified per tick). Other deaths (killed from
  outside, idle) quarantine nothing. Attributed deaths reset the M1-02a candidate crash counters.
- Quarantine table: keyed by artifact_hash, 16 entries (`AGENT_MAX_QUARANTINE`), never evicted. Full: nothing
  added, every native specialization refused with `quarantine_table_full`.
- Refusal: world.specialize of a quarantined hash (checked after admission) answers SU_E_CANDIDATE_FAILED,
  detail `{phase:"quarantine", reason:"artifact_quarantined", artifact_hash, crash_count}`.
- Recovery object: `native: {artifact_hash, world_id, system_id, backend, tier, quarantined, crash_count,
  replaced_pid}` for the first attributed kernel.
- Respecialization: FIFO queue (16). Queued in recovery, serviced by the serve loop after the reply of a
  non-`world.step` request whose reply has no `recovery` member; one entry per service; one retry on
  SU_E_WORKER_FAILED; refusals final. Outcome in world.inspect top-level `specialization`
  (`pending_respecialization`, `respecialization`, `reason`, `quarantined`, `quarantine_table_full`).
- Replay: specialization is NOT canonical state and is not logged. Recovery state equals the VM control run
  whether or not respecialization succeeds (checked by test_native_fault and TX2/TX3).
- Worker seam: `SU_TEST_FAULT_NATIVE_TICK` / `SU_TEST_FAULT_NATIVE_BACKEND`, read only in the native test
  worker (`SU_TEST_FAULT_HOOKS` and `SU_HAVE_NATIVE`), dies with SIGSEGV inside `su_nv_run_system`.

## 5. Deviations
1. Attribution is per world, not per kernel (section 2). A world.step death quarantines every kernel of that
   world.
2. Respecialization is serviced after the reply of a non-tick request (not "at the start of the next
   request"). A synchronous supervisor cannot run admission while a client's world.step is read: if a
   non-tick request is followed immediately by a tick, the tick waits for the admission that the non-tick
   reply triggered. The tick itself never runs respecialization work caused by recovery.
3. Crash-at-tick scenarios are in `test_native_fault` (ctest), not in the harness: the production `sutekh`
   has no seam. The harness TX3 block covers an outside kill with a scalar kernel installed.
4. `native` in the recovery object names the first attributed kernel only; the full list is in
   `world.inspect`.
5. Refusal after admission: the artifact hash is known only after the disposable admission, so admission
   runs before refusal.
6. Retry policy: one retry on SU_E_WORKER_FAILED only.
7. `planning/tasks.json` not updated (outside write scope).
