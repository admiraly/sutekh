## API summary (for the runtime worker)
- Create: `su_world_create_ext(desc, max_entities, &SuWorldSchemaExt{defaults, retired_ids, retired_count, lineage,
  lineage_count}, &w)`; `su_world_create_successor(old, desc with row_count 0, ext, &new)`; then
  `su_world_put_committed(new, id, values, hw)` per field.
- Digests (supervisor switches to recovery): `su_world_recovery_digest(w, out32)`; `su_world_schema_digest`.
- Snapshot: `su_snapshot_capture` emits 0.3 automatically when lineage or retired IDs exist.
  `su_snapshot_restore_world(bytes, len, desc, allow_schema_change, &w, &data_or_NULL, &err)`: plain restore uses
  `allow_schema_change` 0; rollback and recovery use 1 with `desc` NULL (world built from the header).
- Migration: `su_migrate_plan(w, &inputs{migration, transform, lir}, systems[], drop[], &budget, &plan)`;
  `plan.valid`/`plan.reason` (`SU_MIGRATE_REFUSED_*`), `plan.message`, impact per system (`impact`, `reasons`),
  digests, column counts, estimates. `su_migrate_prepare(old, &plan, hooks_or_NULL, &new, timings_or_NULL)`;
  `su_migrate_swap(&live, &plan, new, &retired)`; the caller destroys `retired` after the reply;
  `su_migrate_plan_free`.
- Errors: `SU_E_STALE_REVISION`, `SU_E_SCHEMA_MISMATCH`, `SU_E_UNSUPPORTED_MIGRATION`, `SU_E_CANDIDATE_FAILED`,
  `SU_E_RESOURCE_LIMIT`, stage errors from the parser.

## Deviations and ambiguities
1. Access is not in snapshots. A world restored with `allow_schema_change` gets `SU_ACCESS_READ` on every field;
   installed systems must re-establish access on recovery.
2. The transform IR's `system_id` and `numeric_profile` define the synthesized capsule; the capsule name for a field
   is its destination name (source name when removed). Name collisions are refused. Field IDs must be >= 1 (capsule rule).
3. The engine takes the transform document and IR as bytes. The migration's `document` value is validated as a
   string and recorded, not opened; the caller resolves it.
4. The migration hash is undefined in the contract. Chosen: SHA-256 of `"SUMIGRATE" 0x00` and length-prefixed
   migration, transform and IR bytes. The plan hash binds it to the pre-migration digest and schema digests.
5. A plan's `valid` is false for a removed field used by a system that is not in `drop_systems` (reason
   `field_in_use`); the system is still reported `broken`. Unknown system fields are an input error
   (`SU_E_SCHEMA_MISMATCH`), not an impact.
6. Admission numbers are estimates: `bytes_peak` counts memory added above the resident old world; the spool
   check is `pre + post` against `spool_bytes`.
7. Only 0.2 and 0.3 snapshots can build a world from the header (0.1 has no capacity). A world restored from the
   header is not valid for a 0.1 capture.
8. Swap does not destroy the old world; the caller owns `retired`. Prepare and swap each compute the recovery digest
   (O(state)).
9. Field ID 0 is refused by migration (capsule IDs are positive) but still allowed by `su_world_create`.
10. The event log is runtime state and is not exercised here.
