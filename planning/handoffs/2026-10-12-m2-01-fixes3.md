### TSan triage (item d)

Native TSan tree (`-fsanitize=thread`, Debug, `-DSUTEKH_NATIVE=ON`), `ctest -j2`: **30/34 passed**. Failed: `control`,
`reload`, `snapshot_cp`, `containment`. Migration tests (`migration`, `migration_runtime`, `migration_alloc_points`,
`migration_model`, `migration_alloc_points_selftest`) and `specialize_inflight` pass under TSan. No "data race"
reports in the run log.

Evidence that the cause is environmental (the sanitizer runtime cannot start under a 4 GiB address-space limit):
- The failing lines are `ThreadSanitizer: CHECK failed: sanitizer_allocator_primary64.h:131 ... (0x720000000000,
  0xfffffffffffffff4)`. The second value is -ENOMEM from the TSan allocator's fixed-address reservation.
- Probe: a trivial TSan program (`printf` only, scratch) gives the same CHECK under `ulimit -v 4194304` and
  `ulimit -v 8388608`, and exits 0 with no limit.
- Source: `tests/control/test_control.c`, `tests/reload/test_reload.c` and `tests/snapshot_cp/test_snapshot_cp.c` set
  `cfg.worker_address_space_bytes = 4 GiB` unless `TEST_UNDER_ASAN` is defined. No build defines it, and the
  `snapshot_cp` file defines it only for ASan. `tests/recovery/test_containment.c` takes its cap from
  `SUTEKH_WORKER_AS_BYTES` (4 GiB by default). The fixes2 audit's attempt with `SUTEKH_WORKER_AS_BYTES=0` did not reach
  the three test-configured caps, which is why it still failed.
- Diagnostic tree (scratch, flags only, test source unchanged: `-DTEST_UNDER_ASAN=1` added to the TSan flags):
  `control`, `reload` and `snapshot_cp` **pass**. `containment` still fails there, and **passes** with
  `SUTEKH_WORKER_AS_BYTES=0` in the environment.

Conclusion: not a product defect. It is a test-configuration gap: the no-address-space-limit guard covers ASan but not
TSan. I did not change the guard (triage only). Proposed fix for the owner or the next patch: define the guard for
`__SANITIZE_THREAD__` / `thread_sanitizer` (the same as ASan) and run containment with `SUTEKH_WORKER_AS_BYTES=0`
under TSan. The fixes2 audit's ASan result (33/33) is not re-examined here.
