## What was built

1. **Opt-in tick workers.** `SuSchedTickOpts` and `su_sched_run_ticks_opt` (schedule.c). With workers
   1 (default) every system runs through the serial VM or native path, exactly as before.
   With workers > 1 and rows >= chunk_min_rows, the VM path goes through `su_jobs_run_system_chunked`.
   `su_sched_run_ticks` is a serial wrapper.
2. **Plumbing.** The supervisor reads `SUTEKH_TICK_WORKERS` (1..64) and
   `SUTEKH_TICK_CHUNK_MIN_ROWS` (default 4096) in sutekh_main.c (invalid value: exit 2). It sends
   `tick_workers` and `chunk_min_rows` as internal fields of every world.step, including recovery
   replay. engine.info reports `tick_workers: {workers, chunk_min_rows}`.
3. **Schedule checks at world.create** (worker.c `check_system_effects`, reusing existing codes):
   - Every system is treated as declared parallel, so an unordered write/write or read/write pair is
     refused with SU_E_SCHEMA_MISMATCH. **Behaviour change:** before this, such worlds were accepted.
   - Ordering cycles and unknown edges are refused with SU_E_INVALID_ARGUMENT (su_effects_build).
   - An `after` edge whose target comes later in the capsule list is refused with SU_E_INVALID_ARGUMENT,
     because systems run in capsule order.
   - The effect check runs only at world.create. Installs are not re-checked.
4. **Containment defaults** (existing, now tested): RLIMIT_AS 4 GiB, scrubbed child environment,
   and a 512 MiB spool in the binary (the library default remains 32 MiB).

## Deviations and caveats

- Native kernels run as one call over the whole range even when N > 1 (no row slicing).
- Candidate evaluation (disposable workers) stays serial. Only the live world.step path is chunked.
- The disposable-worker environ check only counts children whose argv ends in `worker`, so it reads the
  environment after exec and not the pre-exec fork copy. TX6 observed one disposable worker.
- The schedule checks only run at world.create. Installs are not re-checked.
- The world runs systems in capsule order; the canonical order from su_effects is not used.
- The row-order mutant result above is an equivalent mutant, not evidence of detection.
- TSan on the full harness binary was not run.
