Not touched: `src/runtime/native_versions.c` (r4 A2), `src/world/*`, `include/*`, `planning/tasks.json`.

Mechanism (as built):
- `SU_SYS_KIND_IR`/`SU_SYS_KIND_HOST`, `SuHostField`, `SuHostOpDesc`, `SuSysEntry.kind/host`, `su_sched_add_host` (declaration must match the descriptor; no VM context).
- `run_host` (first branch of `run_one_system`): views filtered to the declared reads/writes; working copied to staging for every row of each declared write field that is also readable; `run`; commit of the declared write ids in ascending order only on SU_OK.
- Effects: `SuEffectInput.host_declared` takes the declared access bits and skips `check_declared`/derive.
- Candidates: `su_sched_check_candidate` refuses a host system with `SU_E_CAPABILITY_DENIED`.
- Load: `su_host_load` (strict JSON, IR-only keys refused, pin, system_id, schema, profile, schedule block, host object equal to the descriptor). `world.create` host item → registry lookup; no descriptor → `SU_E_CAPABILITY_DENIED`.
- Restore: `CkptSys.kind` written by `ckpt_record`; a host entry is rebuilt from the registry and its capsule; unregistered → `SU_E_SCHEMA_MISMATCH`; a changed capsule → `SU_E_CANDIDATE_FAILED`.
- Hashes: `semantic_hash` = SHA-256 of the sorted-key canonical JSON of the descriptor; `capsule_hash` = SHA-256 of the capsule bytes; `source_hash` = SHA-256 of the empty string.
- Refusals in handlers: `h_internal_specialize_install` (host entry), `h_candidate_evaluate` and `h_internal_specialize_admit` (capsule with a `host` object, via `su_host_capsule_is_host`, before reload), `h_internal_world_migrate_prepare` (any host entry).
- Registry: `host_registry.c` table is empty in M3-04a. Test hook `su_host_registry_test_set` only under `SU_TEST_HOST_REGISTRY`, which only the test translation units define.

## Deviations from the contract (recorded)

1. `numeric_profile`: r3/r4 name `rts_u32_v1`. The engine (`su_lir.c`, `schemas/capsule.schema.json`) recognizes only `u32_mod_v1`. Host records and declarations use `u32_mod_v1`. Owner decision needed (OD-9).
2. `SuHostOpDesc.run` takes `const SuWorld *w` as its first argument. Sections 4.1 and 4.3 read alive and generation, which are not fields and not in `SuInvocation`. r4 kept the three-argument form; the operator needs the world to read entity state.
3. `rts.scatter` field 39 (`incoming`) is declared `read_write`, not write-only: the saturating add reads it (4.3). Contract read set omits it.
4. Write-only declared fields have no working view in `run_host` (`su_world_build_invocation` exposes readable fields only, and `su_world.h` is unchanged). r4's "copy working to staging for every row" is implemented for read-write fields. A write-only host field must store every row itself. Affects M3-04 (spatial writes 21-30 every row). Open: add a working accessor (shared header, owner approval).
5. `su_host_load` takes an expected capsule hash and returns `schema_version` and `layout_generation` (r4 signature is shorter). The loader also checks `capsule_format`, `numeric_profile` and the `schedule.phase` string.
6. Host records use `limits.max_instructions = 1` (the schema minimum; host operators run no IR) and `max_rows = 1000000`.
7. Refusal codes not fixed by the contract: `world.create` host item with no registered operator → `SU_E_CAPABILITY_DENIED`; capsule with a host object in candidate/admit → `SU_E_CAPABILITY_DENIED`; `world.migrate` with a host entry → `SU_E_CAPABILITY_DENIED`.
8. Restore of a checkpoint with an unregistered host descriptor → `SU_E_SCHEMA_MISMATCH` (as r4).
9. `test_host_restore.c` includes `worker.c`, `host_registry.c` and `host_decl.c` directly (with `SU_TEST_HOST_REGISTRY`) to reach the static loader and restore functions. This is a test-only pattern; the product build does not do it.
10. Equivalent mutant recorded (see above).
