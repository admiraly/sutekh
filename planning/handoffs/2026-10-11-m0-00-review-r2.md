2. **Field ID owner: resolved.** §2: "The **capsule `fields` array is the authoritative schema declaration**".
3. **Bindings order: resolved.** `abi.h` SuInvocation: "contains exactly the READABLE fields ... in verified-table order ... matched by field_id". §3: missing/extra field_id -> `SU_E_SCHEMA_MISMATCH`.
4. **Store rule: partly.** M0_CONTRACT §1 decides: "unchanged values are copied with load+store". LIVE_IR §5 still says "Unchanged fields are not copied through registers unnecessarily", which the contract's reading contradicts. The spec text was not amended.
5. **Error policy and missing code: partly.** §1 adds `SU_E_MISSING_STORE` (20) and a fixed first-error order. Gaps remain (see new items N2, N3).
6. **Staging and context lifecycle: partly.** §3: commit is a copy; overlap is byte-range; context is created by M0-04; NULL ctx -> INVALID_ARGUMENT. The per-row register capacity of the context is still not stated, though `SU_LIMIT_REGISTERS` exists.
7. **Wrapper error mapping: partly.** §3 now maps NULL, struct_size, abi_version, stride, elem_type, counts, generation, length, alias, NULL ctx and row limit. Still unmapped: access-bitmask mismatch and nonzero `SuOutputs.reserved`.
8. **Hash encoding: partly.** §5 pins u32 LE, u32 length-prefixed UTF-8 strings, register numbering from 0, source/capsule hash coverage, layout_generation exclusion, and empty referenced hashes. Still unstated: the mapping of capsule `"u32"` to `SU_TYPE_U32` and of `read`/`write` to `SU_ACCESS_*`; whether `schema.version`, `schedule`, `limits`, and `capsule_format` are excluded.
9. **Snapshot: partly.** §6 pins `snapshot_format="0.1"`, columns keyed by name, and restore assigning a new revision. Unstated: widths or format of `world_revision` and `entity_ids`, and the snapshot id that `restored_from` refers to.

## New contradictions and gaps (r2)

Blocking:

- **B1. Cross-reference error.** `abi.h` (SuInvokeV1Fn comment) says violations return "the status in M0_CONTRACT.md section 4". The wrapper mapping is in §3; §4 is tick/publish.
- **B2. Limit contradiction.** M0_CONTRACT §3 calls `SU_LIMIT_ROWS` "runtime-configurable default". `ir.h` defines it as a fixed `#define` (r1 non-blocking 7 still open). Pick one.
- **B3. First-error classification is ambiguous.** §1 places "key/shape/type errors (`SU_E_TYPE`)" before instructions. The fixtures need:
  - `invalid/unknown_opcode` -> `SU_E_UNKNOWN_OPCODE` at instruction 2. This is correct only if unknown opcodes are instruction-level. But `schemas/` rejects the same file at schema level, and an implementer mapping schema failure to `SU_E_TYPE` would get a different code.
  - `invalid/wrong_store_type` and `bool_as_u32` -> `SU_E_TYPE`. These are instruction-level type checks. §1 does not say whether they belong to the pre-instruction bucket or to the ascending-instruction bucket.
  State both explicitly.
- **B4. Capsule and schema errors are outside the ordering.** §1's fixed order covers IR errors only. It does not place `SU_E_SCHEMA_MISMATCH` (query/system_id/profile mismatch, duplicate field id or name) or capsule-load errors relative to IR errors.
- **B5. LIVE_IR §5 conflicts with M0_CONTRACT §1** on copying unchanged writable fields (see finding 4). Amend LIVE_IR §5 or record the contract as an explicit override.

Non-blocking:

- **N1.** Two conflicting negative-case manifests exist: `examples/negative_cases.json` (7 cases, capsule `movement.capsule.json`, includes `duplicate_key`, `unknown_opcode`, `duplicate_register`) and `tests/fixtures/negative_cases.json` (7 cases with per-case capsules, includes `too_many_instructions`, `denied_read`). They are disjoint in content. The contract names neither as authoritative.
- **N2.** `tests/fixtures/invalid/store_same_field_twice` expects `SU_E_UNDECLARED_WRITE`. §1 now codifies that for a second store, but the fixture note still says "judgment call, see handoff" and "no dedicated code exists". The note is stale. No duplicate-store code exists.
- **N3.** `examples/invalid/undeclared_write` also omits the `position_x` store. It yields UNDECLARED_WRITE only because instruction errors precede end-of-body. No fixture exercises `SU_E_MISSING_STORE`, and no fixture exists for `SU_E_SCHEMA_MISMATCH`, `SU_E_INVALID_ARGUMENT`, `SU_E_INTERNAL`, or alias.
- **N4.** `too_many_instructions.lir.json` (4097 instructions) has no store at all. It is correct only because the limit check precedes end-of-body. "Input size/depth limits" does not clearly include instruction count.
- **N5.** Snapshot §6: `tick` as a "decimal u64 as JSON integer" exceeds exact double range for large values. State the parser requirement. `restored_from` refers to a snapshot id that §6 does not define.
- **N6.** `abi.h` `SuOutputs` has no `abi_version`, though §3 says the wrapper checks abi_version generically.
- **N7.** `SuColumnBinding.data` is `void *` for inputs (r1 non-blocking 1, still open). `SU_OPERAND_NONE` equals `0xFFFFFFFF`, a legal const value (r1 non-blocking 2, still open).
- **N8.** AGENT_RPC §5 error list is not updated for codes 18-20 (r1 non-blocking 8).
- **N9.** Hash: §5 field operand replacement is per-opcode slot (LOAD/STORE `a`); this is only implied by the ir.h table. Say so.
