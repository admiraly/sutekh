## 6. Design

**Capture** (`su_snapshot_capture(w, desc, rev, manifest, n, out)`):
- Refused inside a tick.
- The `SuWorldDesc` is the schema source. The world exposes no accessor for schema id, versions, names, or entity IDs, so capture cross-checks the desc: row count, field count, layout generation, each field's name resolves to the same committed column, and entity IDs match the canonical encoding.
- Output is compact JSON, fixed key order, fields ascending by id, columns keyed by name. Identity is SHA-256 of the bytes.

**Parse** (`su_snapshot_parse`), in order:
1. Size over 16 MiB: `SU_E_RESOURCE_LIMIT`, before any read or allocation.
2. Empty input, syntax, or invalid UTF-8: `SU_E_PARSE`.
3. Duplicate key: `SU_E_DUPLICATE_KEY`.
4. Unknown or missing keys, wrong JSON types, bad `snapshot_format`, out-of-range numbers, non-u32 field type, column length mismatch, malformed hash or system ID, non-canonical encoding: `SU_E_TYPE`.
5. Schema ID, schema version, layout generation, numeric profile, field table, row count, entity IDs vs the target desc: `SU_E_SCHEMA_MISMATCH`.

Canonical form is enforced: the input must equal its own re-encoding byte for byte. Whitespace, key order, and escape variants are rejected, so identity is well defined.

**Restore** (`su_snapshot_restore(desc, data, &world, &manifest, &n)`):
- Builds a **new** world. The live world is never touched.
- Columns are set with `su_world_init_committed` on a fresh tick-0 world, then the tick is advanced to the snapshot tick with systemless `begin_tick`/`publish` pairs.
- The caller swaps its instance pointer only on `SU_OK`. This is the no-partial-restore guarantee.
- Cost is O(snapshot tick) publishes plus one copy of the columns. This is a limitation: see section 7.
- Manifest is returned by pointer into `data`, valid until `su_snapshot_data_free`.

**Checkpoint store** (`src/runtime/checkpoint.h`):
- `su_checkpoint_store_create(0)` gives retain = 8. Max 1024.
- FIFO eviction on create. Ids are monotonic and never reused; `get`, `info`, and `release` on an evicted or released id return `SU_E_INVALID_ARGUMENT` with NULL output.
- Double release is safe and returns an error without changing state.
- `su_checkpoint_create` times the capture with `su_platform_monotonic_ns`. `capture_ns_known` is 0 when the clock fails, and `capture_ns` is then 0.
- `su_checkpoint_stats` reports `retained_bytes` (sum of snapshot bytes), `overhead_bytes`, counts, and last capture time.
- Peak during create is retain + 1 snapshots, because the new capture finishes before the oldest entry is evicted.

Error mapping for restore by checkpoint: an unknown or evicted checkpoint returns `SU_E_INVALID_ARGUMENT`.

## 7. Recommended `su_world` accessors (not implemented; `su_world.[ch]` is out of scope)

1. `uint32_t su_world_restore_committed(SuWorld *w, uint64_t tick, const uint32_t *const *columns, uint32_t field_count)`: in-place restore of committed columns and tick, valid only when idle and the field table matches. This removes the O(tick) replay, and the worker could then restore in place.
2. `su_world_schema_info(...)` or equivalent: schema id, schema version, entity IDs, field names and types. This removes the need for the caller to pass a desc that must be trusted and cross-checked.

Until these exist, restore uses the fresh-world path above.

## 8. Recommended control-plane methods (for the control-plane owner)

Not implemented. Proposed shapes:

- `world.snapshot` params `{world_id}`. Result `{checkpoint_id, snapshot_id, tick, bytes, capture_ns|null, world_revision}`. Errors: `SU_E_INVALID_ARGUMENT` (inside a tick), `SU_E_RESOURCE_LIMIT`.
- `world.restore` params `{world_id, expected_world_revision, checkpoint_id}` (or `snapshot_id` once snapshots are persisted). Result `{world_id, world_revision (new), tick, restored_from: snapshot_id, semantic_manifest: [{system_id, semantic_hash}]}`.
  - Stale revision: `SU_E_STALE_REVISION`, checked before any work.
  - Unknown checkpoint: `SU_E_INVALID_ARGUMENT` (or a dedicated code; the contract does not define one).
  - Parse failures: the mapping in section 6.
  - Restore failures leave the instance unchanged; the new revision is assigned only on success.

The restore flow in the worker: look up checkpoint, `su_snapshot_parse`, `su_snapshot_restore`, then swap the instance's `SuWorld *` and destroy the old one. Any `SuExecContext` bound to the old world must be checked by the worker owner.

## 9. Deviations and notes

- The `fields[].type` value is the string `"u32"` (matching capsule JSON), not the numeric `SU_TYPE_*` code. The contract does not fix the spelling.
- The snapshot-specific error mapping in section 6 is my choice; the contract's section 4 does not list snapshot codes. Please confirm or amend.
- Capture transiently allocates a canonical copy of the world to read entity IDs. This doubles transient memory during capture. The accessor in section 7 removes it.
- Only the example world (`examples/world.json`, `demo.actor`, fields `position_x`=1 and `velocity_x`=2 from `examples/movement.capsule.json`) is exercised by the tests. The ticks in the test are a hand-written position-plus-velocity system, not the VM.
