## Design notes (what the code does)
- Lowering: each SU-LIR register is a 4-byte stack slot; column pointers copied once at entry;
  row loop with r12 (row), r13 (row count), rbx (args). Zero rows return before any push.
  Callee-saved registers touched: rbx, r12, r13 (saved). No calls, no red zone, no xmm.
  Frames over one page are probed from the top. Frame = round16(4R + 8(in+out)); max 4096 registers.
- Bool slots hold 0/1; LT is unsigned (`setb`); MUL is 32-bit `imul` (same low bits).
- Code is assembled into a `CodeHolder` with `Environment(Arch::kX64)`. `JitRuntime` is not used.
  `finalize()`, `has_unresolved_fixups()` check, `flatten()`, `copy_flattened_data()`. The C side maps
  RW, copies, `mprotect(R+X)`, `__builtin___clear_cache`. Never RWX.
  `relocate_to_base()` is not called: the kernel has no absolute references and no base address;
  the unresolved-fixup check covers that.
- Source map: one range per instruction, from `CodeHolder`/`Assembler::offset()` before and after
  each instruction's emission.
- Artifact hash: SHA-256 over domain tag, ABI version, artifact format, backend id/version, host ABI,
  lowering flags (0), layout generation, caps, semantic hash, AsmJit commit (from
  `third_party/asmjit.lock.json` at configure time).
- Wrapper: mirrors the `su_vm_invoke_v1` checks in order. The VM's checks are file-local, so they are
  mirrored (not shared). Test compares statuses against the VM.
- Caps: only `SU_NCAP_X86_64_SCALAR` is accepted. Any other caps value returns
  `SU_E_CAPABILITY_DENIED` (the contract has no `SU_E_UNSUPPORTED`).
- Contract note: the M1 contract says "65 core+x86 .cpp files". At pinned commit
  `0d7f01052f2d3f6d6b9bb6714ef32bd7b80177eb` there are 41 core+x86 non-test `.cpp` files plus 4 `axl/`
  support files = 45. The 4 `axl` files are required for linking (arena, vector, hash), so the
  build uses 45 files. Contract/owner should correct the count.

## Unrun or not verified
- Win64 prologue and argument register (rcx) are emitted under `#if defined(_WIN32)` but not run,
  not compiled on Windows, and have no Win64 unwind data. Reported as not run (M1-05).
- Kernel stack alignment is by construction (asserted in the trampoline's call setup) but not probed
  from inside the kernel. No probe kernel was written.
- AVX2 and the AVX2 caps path: not in scope. `SU_NCAP_X86_64_AVX2` is refused.
- Heap leaks in the failure path were checked only indirectly, by ASan leak detection in the ASan run.
  Mapping counts were checked directly.
- Underrun detection for columns is at page granularity (guard pages before/after; the column ends
  exactly at the after-guard, so overruns are exact).
- Concurrency: the injection hook is process-global; the backend is not thread-safe (documented).
- The W^X child-fault check accepts any nonzero child exit as a fault. Under ASan the fault is
  reported by the sanitizer runtime, not by a signal.
