## Design notes and deviations

1. Cast in `boundary()`: `su_world_entities_working` returns `const SuEnts *`; the runtime casts it to mutable
   to call `su_ents_despawn` at the boundary. `src/world` is out of this write scope. A tiny additive accessor
   `su_world_entities_working_mut` would remove the cast (owner decision).
2. Record order within a row (deviation from contract section 2). `su_cmdq` keeps one per-row counter per
   record kind (`row_s` for despawn records, `row_e` for events), and its append API takes no `seq`. A row that
   both despawns and emits therefore gets seq 0 for both, and the event sorts first on equal keys. The contract
   asks for one emission order per row shared by both kinds (despawn before emit in `ok_valid`). The test oracle
   encodes the implemented order and says so. Fix needs an append API with the VM's `seq` (owner: M2-00b,
   `src/world/entities/su_cmdq.c`).
3. Failed-index semantics: `failed_index` is the failing system index, or `UINT32_MAX` for a boundary or publish
   failure and for a whole-tick overflow.
4. Per-buffer memory: each (system, chunk) buffer holds `min(1024 * per_row_cap, per_tick_cap)` entries for
   structs and events. For a 1,000,000-row entity world this is about 977 chunks times that size per system (about
   300 MB at per-row caps of 4). The tests use 5,000 rows. Not measured at 1M rows (not run).
5. Per-row caps: one cmdq per-row cap per call, taken as the maximum of the entity-op modules' declared caps.
6. The cmdq and its buffers are created per `su_ent_run_ticks` call (outside a tick) and reset per tick. The
   event log persists in `SuEntRt`.
7. `zero_dead` after every system: a per-row system cannot observe a dead row's stale staging value because dead
   rows are skipped (entity systems) and `su_world_publish` zeroes dead rows again. Mutation proof: removing the
   per-system call survives (equivalent under the current design). Kept for the contract's stated invariant.
8. The despawn zeroing at the boundary is also covered by `su_world_publish`; removing the explicit call
   survives for the same reason.
