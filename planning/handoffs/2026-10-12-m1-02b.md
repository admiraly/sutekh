## 2. Design
- `native_versions.[ch]` (compiled only with `SU_HAVE_NATIVE`): process-global registry of at most
  `SU_NV_MAX_ARTIFACTS` = 32 live artifacts (4 worlds x 8 systems). Callers hold a sequence handle, not a
  pointer. States PREPARED, ADMITTED, INSTALLED, RETIRING; release frees at once unless an in-flight count
  is non-zero. Every kernel call is wrapped in the in-flight count. Single-threaded (documented).
- Admission (`su_nv_admit`): VM vs kernel through `su_vm_invoke_v1` / `su_native_run_checked`, row counts
  0,1,7,8,9,17,1024, aligned and unaligned columns, edge and seeded words, 42 cases for `movement`.
- Schedule: `SuSysEntry.native_seq` (0 = VM). `su_sched_run_ticks` dispatches to the kernel; entry destroy
  releases it. Reload already destroys the replaced entry after publish, so a code-only install drops the
  kernel at that boundary.
- Worker `world.specialize`: checks revision, optional semantic hash, system id, backend and host caps;
  compiles, admits, recompiles, requires artifact_hash equality, installs; the old kernel is released.
  World revision and worker PID unchanged.
- Agent: routes `world.specialize` (relays the worker answer), advertises it in `capabilities`, and adds
  `native.specialization` to `engine.info`. Default build: none of this is compiled.
- Recovery: kernels are not logged or checkpointed. Rebuilt and restored worlds start on the VM tier.

## 4. Deviations
1. Admission and the recompile run in the active worker, not in a disposable worker (C07 asks for isolation
   of unreviewed candidates). The lowering is trusted compiler output, but a native fault here kills the
   active worker. Disposable isolation is not built.
2. Admission uses the seeded corpus only. The system's own test cases are not in it.
3. `world.inspect` has no per-system tier field of its own; tier is in `semantic_manifest[].execution_tier`
   (native builds only).
4. The reply field `world_revision` is unchanged; the spec left this open.
5. No `world.specialize` replay after recovery (M1-02c, as the spec asks).

## 5. Unrun or missing checks
- Clang build and clang sanitizers: not run.
