## 1. Product code changes

- `src/runtime/worker.c` `internal.stats`: new field `entity_runtimes` (used worlds with an entity runtime). Worker only;
  not advertised, not forwarded by the supervisor (same as the other internal.stats fields).
- `src/runtime/schedule.h` / `entity_tick.c`: test seam `SuSchedTickOpts.seeded_completion` and `completion_seed`. When set,
  every entity system's chunks complete in a seeded permutation per (tick, system) via `su_jobs_pool_run(order)`. Default 0:
  no behaviour change. Scratch permutation buffer allocated per tick run and freed in the cleanup path.
- No defect found in the merge, admission, or recovery logic. Equivalent-mutant finding in section 3 (MX22).

Why MX18 survived before (established by reading): `sync_after` with `LOG_NONE` does not append, and `ticks_since_ck` is
unchanged, so a despawn only leaves the log in a process that later dies. The existing tests never do that: test_recovery
has no despawn; in TX7 the only pre-crash despawns are refused (no log entry), the successful control-plane despawn happens
after the kill, and the system-side despawn (`despawn_self`) is part of the logged STEP and is replayed by the step.

- The seeded completion seam is C-only; the binary has no env switch for it (TX8 covers N through the binary).

- MX22 is equivalent (see section 3), so the per-system zeroing is not independently proven; publish-time zeroing is in `src/world`
