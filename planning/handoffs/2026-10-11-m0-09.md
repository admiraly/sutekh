## Method and limits (honest)
- T12 method: `strace` (6.8) exec-family tracing of the demo process tree, including all forks and threads. No fallback (PATH stubs, unshare, /proc polling) was implemented because strace is installed; the fallback is not needed here.
- strace sees exec-family syscalls only. In-process code generation or any code path that avoids exec would not appear; the static scan and source review cover that only partially. Native code generation is a later milestone, so this is not a gap for M0 gameplay.
- strace slows the traced tree. The demo's timings are from the untraced run only.
- The edit window is the demo's wall clock (time.time_ns) from the scratch edit to the install reply, compared with strace's CLOCK_REALTIME stamps (-ttt). The whole-run check does not depend on the window, so a mismatch in the clocks can only weaken the window-specific figure, not the whole-run figure.
- Timing numbers are single-run actuals, with no target comparison. TEST_SPEC declares none for this demo.
- The demo's expectations come from `tests/harness/reference_eval.py` (the independent evaluator). The v2 LIR is produced by a transform and cross-checked against `examples/movement_v2.lir.json`.
- Demo: install is at the current tick only (engine rule). The "future effective tick" is planned as E before the edit and reached by stepping under v1; the install then takes effect after tick E.
- Demo: the scratch edit lives under `build/demo-scratch/` (inside the serve root, because the engine refuses paths outside it); removed at exit unless `--keep-scratch`.
- Demo: the rejected invalid edit is a submit-time rejection. The evaluation-failure rejection (install refused with `SU_E_CANDIDATE_FAILED`) is covered by harness T06, not repeated here.
- Demo: restore's worker identity is checked as "same worker process" (PID and start time), which is what the engine currently does; the spec does not state this as a contract for restore beyond the harness.
