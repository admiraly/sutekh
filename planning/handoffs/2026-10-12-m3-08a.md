# M3-08a handoff: exact per-root memory accounting (OD-10)

Task: M3-08a (contract `planning/contracts/M3_RTS_CONTRACT.md` r4, sections 9.3, 9.5, OD-10, task table, Appendix A).
Scope: `src/world/` accounting API (additive), tests, handoff. Two files outside `src/world/` are needed for the test target and are listed under Deviations.

## Implemented

Byte accounting API. Every figure is the sum of the sizes the world asked the allocator for and still holds. There is no RSS, no allocator overhead, and no measured timing.

- `su_world_memory(const SuWorld *, SuWorldMemory *)` (`src/world/su_world.h`, `src/world/su_world.c`)
  - `columns_committed`, `columns_working`: `fields * max(capacity, 1) * 4`
  - `columns_staging`: same, for fields whose staging column exists (WRITE access)
  - `entity_table`: committed plus working entity tables
  - `metadata`: world struct, schema and field name copies (with NUL), field table, three column pointer arrays, binding arrays, retired-ID and lineage arrays
  - `total`: sum of the five
- `su_ents_memory_bytes(const SuEnts *)` (`src/world/entities/su_ents.{h,c}`): struct plus gen, ext, alive, avail, chunk_alive, chunk_free, summary arrays, with the same `max(n,1)` rules as `su_raw_new`.
- `su_cmdq_memory(const SuCmdQ *, SuCmdQMemory *)` (`src/world/entities/su_cmdq.{h,c}`): `structural` (sbuf), `events` (ebuf), `scratch` (m_cmd, t_cmd, rec, m_evt, t_evt, fin), `bookkeeping` (meta, offsets, cursor, heap, struct), `total`.
- `su_evlog_memory_bytes(const SuEventLog *)`: struct plus ring.

Not included, by design: the spatial grid (runtime), the checkpoint spool and snapshot bytes (snapshot owner; not owned by the world root), and the cmdq as used by the runtime tick. These are documented in the header. The contract's 9.3 event-log and spool terms are not covered by `su_world_memory`.

No `internal.stats` exposure path was added. The contract (r4) names none, and I found no `internal.stats` reference in it.

## Tests

- `tests/world/test_world_acct.c` (ctest name `world_acct`)
  - Counting seam: `tests/world/acct_seam.h` is force-included only into `su_world.c`, `su_ents.c` and `su_cmdq.c`, compiled into the object library `su_world_acct_objs`. The seam's live-byte count is the true heap usage of those sources, and the test asserts zero live blocks at exit.
  - Column categories checked against `fields * max(rows,1) * 4` and the writable-field count, for 7 configurations (capacity 0 with fields, 0 and 1 and 63, 64, 65, 1024, 1025 boundaries, a 2-chunk table).
  - World `total` equals the seam live delta across create. Entity table equals twice the seam-measured standalone table. `su_ents_memory_bytes` equals the seam delta for 10 capacities.
  - Schema name length, retired IDs and lineage: metadata moves by exactly the byte amounts the input adds.
  - Tick, commit, publish and spawn move no bytes and allocate nothing.
  - Successor world counted. Command queue structural, event and scratch sizes checked against formulas from the config. Event log ring grows by exactly 100 records per 100 added.
- `tests/world/acct_mutants.py`: 17 killable mutants, one per category and extra per-field variants, plus 3 honest equivalents that must survive. It applies each edit to a scratch copy under the work dir and checks the edit matched exactly once. Mutants are not kept in the repo.

## Deviations and unrun checks

1. `CMakeLists.txt` is outside the lease. A test-only block (`su_world_acct_objs` object library compiled with the seam, `test_world_acct`, ctest `world_acct`) was added. Nothing else in CMake changed. Needs owner ack or removal.
2. OD-10 is marked "needs owner approval" in the contract. I implemented as the task instructed. I did not verify an approval record. The contract text is not updated, so 9.3 still reads "estimates until M3-08a". The table's per-row estimate figures are not re-stated here.
3. Event log, spool, spatial grid, runtime cmdq placement and snapshot bytes are not in `su_world_memory`. They are either outside world ownership or live in another owner's code. No measured RSS or `VmHWM` is reported.
4. The "per-category bytes match 9.3 within stated tolerance" acceptance is interpreted as exact match to the allocator's sizes. The 9.3 analytic values were not compared with a measured RSS figure, because M3-08a does not measure RSS.
5. The seam test compiles the three world sources itself, so the release binary is not the code being counted. The release and debug full builds do contain the same accounting functions (they are linked into the normal world library). The seam covers allocations in those functions only.
6. Not run: ThreadSanitizer (not part of the task); the full harness on a debug binary; native lane tests (the native build was not part of this patch).
