## Build and run (from the repository root; S = scratch directory)
The library sources are the ones the test links. `su_vm` requires `su_world` and `su_ir`, which are all compiled here directly.

1. Worker stub (strict):
   `gcc -std=c17 -D_POSIX_C_SOURCE=200809L -Wall -Wextra -Werror -pedantic -Iinclude -Isrc src/ir/*.c src/world/*.c src/vm/*.c src/agent/*.c src/runtime/*.c tests/control/worker_stub.c -o S/worker_stub`
2. Control test (strict):
   `gcc -std=c17 -D_POSIX_C_SOURCE=200809L -Wall -Wextra -Werror -pedantic -Iinclude -Isrc src/ir/*.c src/world/*.c src/vm/*.c src/agent/*.c tests/control/test_control.c -o S/test_control`
3. Run: `S/test_control S/worker_stub` (argv[1] = worker executable; argv[2] optional project root, default cwd, which must be the repo root; env `SU_TEST_SCRATCH` optional, default `$TMPDIR` or `/tmp`).
4. Clang: the same two commands with `clang`.
5. Sanitizers: the same two commands with `-g -O0 -fsanitize=address,undefined -fno-sanitize-recover=all`. The test then sets RLIMIT_AS to 0 automatically (`__SANITIZE_ADDRESS__` or `__has_feature(address_sanitizer)`).

## Contradictions and deviations (for the integrator and contract owner)
1. Spec says capsule verification is "supervisor-side only". The worker must hold a verified module to run the VM, and the module cannot be passed across the process boundary. The worker therefore re-runs `su_lir_verify` on the same paths and checks the hashes the supervisor recorded (`SU_E_CANDIDATE_FAILED` on mismatch). The supervisor verifies at submit time.
2. Candidate bytes are not kept in memory. The supervisor records paths and hashes at submit, and the disposable worker re-reads and hash-checks them. A file changed in between fails the evaluation (time-of-check/time-of-use is detected, not prevented).
3. `candidate.evaluate` is synchronous and returns the result directly. AGENT_RPC describes an asynchronous job ID; that is not implemented.
4. `capsule.submit` accepts only `capsule_path`. AGENT_RPC's example includes `expected_world_revision`. Capsule submission is creation-only, so the parameter is rejected rather than ignored.
5. `world.create` takes one `capsule_path` (multiple capsules are not implemented). `world.step` requires `expected_world_revision` and caps `ticks` at 100000.
6. Protocol-version mismatch returns `SU_E_TYPE` (the spec does not assign a code). Unparseable requests return `"id": null`.
7. `engine.info` adds `active_worker` (pid, 0 when none) and `process` (role, pid) beyond the listed fields. Documented in the handler.
8. Single active worker holds up to 4 worlds. Worker death loses them (no checkpoint recovery yet; that is M1+ per HOT_RELOAD section 5).
9. `world.inspect` default limit 16, max 256.
10. The `SU_E_INTERNAL` code is not produced by the control plane.

## CMake wiring for the integrator (not applied)
```
add_library(su_agent STATIC
    src/agent/su_proto.c src/agent/su_path.c src/agent/su_module.c
    src/agent/su_proc.c src/agent/su_agent.c src/runtime/worker.c)
target_include_directories(su_agent PUBLIC src "${SUTEKH_CONTRACT_INCLUDE}")
target_link_libraries(su_agent PUBLIC su_vm su_world su_ir)
sutekh_apply_warnings(su_agent)

add_executable(test_control tests/control/test_control.c)
target_link_libraries(test_control PRIVATE su_agent)
sutekh_apply_warnings(test_control)

add_executable(worker_stub tests/control/worker_stub.c)
target_link_libraries(worker_stub PRIVATE su_agent)
sutekh_apply_warnings(worker_stub)

add_test(NAME control COMMAND test_control $<TARGET_FILE:worker_stub>
         WORKING_DIRECTORY "${CMAKE_CURRENT_SOURCE_DIR}")
```
`su_agent` must be declared after `su_vm`. `sutekh_apply_warnings` is added to the library, and the test targets need `-D_POSIX_C_SOURCE=200809L` (or the `.c` files define it themselves; they do). The POSIX-only sources must be excluded on Windows.

Main wiring for `src/platform/sutekh_main.c` (integrator owns it):
- `sutekh serve [--root DIR]`: build `SuAgentConfig` with `project_root` = DIR (default cwd), `worker_argv` = `{self, "worker", NULL}` where `self` is `/proc/self/exe` on Linux (absolute, so the `/` check passes), `request_timeout_ms` = 0 (default), and `worker_address_space_bytes` = a chosen limit. Then `return su_agent_serve(0, 1, &cfg) == 0 ? 0 : 1;`.
- `sutekh worker`: `return su_worker_main(0, 1);`.
- Diagnostics belong on stderr only. stdout carries protocol lines only.
