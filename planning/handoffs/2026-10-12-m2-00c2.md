## Deviations and decisions for the owner

1. Caps are counted per kind: `despawn_self` count against `max_struct_per_row`, `emit_event` count against `max_events_per_row`. The contract text reads as a single combined count; I chose per kind to match the names. Owner to confirm.
2. A capsule `ir_version` key was added (optional; absent means 0.1). The contract requires agreement but no capsule key existed. Owner to confirm the schema change.
3. Native refusal covers every 0.2 module (`ir_version_minor >= 2`), not only those containing 0.2 ops. Stricter than the contract's "modules containing any 0.2 op".
4. `su_vm_context_set_entity_view` cannot check that the `alive` / `generations` arrays cover the call's row count. The caller guarantees it.
5. Dead rows are skipped before the store-check loop, so a dead row never triggers `SU_E_INTERNAL` for an unstored field.
6. The 0.2 hash pin (`cbd6d237…682d`, `ok_valid`) is a regression pin of this encoding, not an external vector.
7. The fixture generator is in scratch (`make_ir02.py`), not committed; the fixture files are committed as data. `tests/harness/` is outside this scope.
8. Pre-existing: `su_lir.c` line 837 (HEAD) has a `-Wconversion` warning; it fails only under `-Wconversion`, which the project does not enable. Left alone.
