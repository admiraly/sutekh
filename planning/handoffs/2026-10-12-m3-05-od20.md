# Handoff: M3-05 slice 1, per-system structural caps (OD-20)

Scope: contract 9.5 and OD-20 only. Not in this slice: world.set_fields, world.spawn_batch, Q2 liveness refusal,
recovery-log entries, the gates T-RTS-LOAD/CTRL/REPLAY/CAPS, and docs/AGENT_RPC.md.

## Change
- `su_cmdq_create_ex` takes per-system per-row struct and event caps (0..64 each). `su_cmdq_create` is the uniform
  form. A system with cap 0 gets an empty buffer, so any append from it overflows.
- `su_ent_run_ticks` and `su_ent_budget` size buffers per system: only `uses_entity_ops` systems have a cap
  (`sys_row_caps`). Before, the global maximum over those systems applied to every system.
- The memory report counts the two per-system cap arrays (2 x nsys x 4 bytes).

## Evidence
- Dev build: `python3 tools/dev.py build --profile dev` succeeds. ctest 30/30 (includes new `cmdq_percap`).
- Native lane (`cmake -DSUTEKH_NATIVE=ON`): build succeeds. ctest 42/42.
- `test_cmdq_percap`: 15 checks, 0 failures. Covers a zero-cap system refusing appends, its buffer size, equality of
  uniform and per-system forms, and argument refusals.

## Unrun
- The 699,050 ceiling and the 844 to 684 bytes-per-row figures in the contract were not re-measured. Budget changes are
  checked by the existing tests only.
- No benchmark. No RSS measurement.
