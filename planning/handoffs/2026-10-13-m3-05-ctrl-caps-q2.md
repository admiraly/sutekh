## Change
- **Q2 (owner decision recorded in planning/status.json, "Q2 liveness refusal still to do in M3-05").** A
  `formation_slot` other than NONE must name a live row of the committed state.
  - Engine `worker.c`: `spawn_row_parse` (spawn and spawn_batch; the batch is checked against the state before the
    call) and `h_world_set_fields` (only when the payload names `formation_slot`). `SU_E_TYPE`.
  - Model: `World.check_formation_live` (`bench/rts/ref/model.py`), called by `World.spawn`, by the spawn_batch
    validation of `bench/rts/replay/rts_replay.py`, and by its `_set_fields`. The model's `_set_fields` also bounds
    `formation_slot` by capacity now, which closes the engine/model divergence noted in the spawn_batch handoff.
  - `tests/rts/ref/checks.py` `check_gather_known_answers`: the dead-slot-at-current-generation state is no longer
    reachable through spawn; the check asserts the Q2 refusal, then builds that state white-box so mutant M3-M24 is
    still caught at operator level (the same treatment as Q3). `tests/rts/ref/m3_control_mutants.py` spawns into a
    world with a live anchor at slot 0 so each check is judged by the rule under test.
- **M3-M28 config check** (`worker.c` `h_world_create`): an `rts` world with `max_struct_per_tick` or
  `max_events_per_tick` below its capacity is `SU_E_RESOURCE_LIMIT` at creation (contract 9.4, T-RTS-CAPS-1 N-3).
- **set_fields order fix**: staleness is checked before the duplicate-slot check, so a stale handle naming a live
  entity's slot is `SU_E_STALE_HANDLE` as in the reference model (was `SU_E_INVALID_ARGUMENT`). Found by the
  engine/model comparison of T-RTS-CTRL-1.
- New supervisor-level tests (ctest): `rts_ctrl_engine` (`tests/rts/load/test_ctrl_engine.py`, every case compared
  with the model: domains at boundary+1 in spawn, spawn_batch and set_fields, D1 defaults and read-back through
  `world.inspect {entity}`, D2 rules, writable set, unknown field, stale and duplicate entities, stale revision, Q2,
  and the 1,024-entity maximum set_fields with one revision bump) and `rts_caps_engine`
  (`tests/rts/load/test_caps_engine.py`: CAPS-1 config refusal; CAPS-2 kill-all tick serial, with
  `event_log_max = 1`, and with two tick workers chunked from one row; spawn 16 / kill 8 / spawn 8 / kill 16; alive
  counts per tick and the death tick from the model).
- `test_load_engine.py` case (a) fills slots 0..1023 first so the near-maximum rows can name live slot 1023.
- `docs/AGENT_RPC.md` section 18 records Q2, the creation caps check and the set_fields check order.
