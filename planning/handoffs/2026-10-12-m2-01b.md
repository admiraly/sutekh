## Implemented
- Worker (`src/runtime/worker.c`): `internal.world.migrate_plan` (estimates, validity; changes nothing),
  `migrate_prepare` (successor world and replacement schedule built aside; every installed system replaced or
  dropped exactly once, replacement capsules reloaded with their recorded hashes, layout generation checked),
  `migrate_swap` (atomic publication: registry transactions, entity runtime move, `SU_EVENT_MIGRATED` append,
  `su_migrate_swap`, old schedule freed so its native kernels are released), `migrate_abort`,
  `create_from_snapshot` (recovery of a migrated world from the snapshot header and capsules), `restore_schema`
  (rollback). `world.inspect` adds `layout_generation`, `migration_lineage`, `schema` (per field: id, name, type,
  default, used, access) and `needs_resubmission` (always `[]` after a commit). The world's descriptor now comes
  from the world's own schema (unused fields included), so migrated worlds capture and restore.
- Supervisor (`src/agent/su_agent.c`): `world.migrate_plan` (spools the documents, stores a plan bound to the
  revision), `world.migrate_commit` (pin the pre-migration checkpoint; prepare; swap; `LOG_MIGRATE`; mandatory
  post-commit checkpoint before the reply; a worker death during that checkpoint recovers, replays the logged
  migration and retakes the checkpoint; no room rolls back to the pin with `SU_E_RESOURCE_LIMIT`
  `error.detail.reason = post_commit_checkpoint`), `world.migrate_rollback` (restores the pin as a new revision,
  `LOG_ROLLBACK`, reports `changes_lost` and `discarded_ticks`). Log kinds `LOG_MIGRATE` (5), `LOG_ROLLBACK` (6);
  the replay loop was split into `replay_log` and re-runs both from the spool; recovery of a checkpoint with the
  `migrated` flag uses `create_from_snapshot` instead of the fixture. Spool references cover pins, plans and logged
  documents. Capabilities list extended with the three methods.
- Crash seam (test builds only, `SU_TEST_FAULT_HOOKS`): `SUTEKH_TEST_KILL_STAGE` with `migrate.prepare`,
  `migrate.swap` (after the publication, before the reply), `migrate.capture` (before the post-migration checkpoint
  file), `migrate.step` (first step after it), `migrate.rollback` (after the restore, before the reply);
  `SUTEKH_TEST_KILL_TOKEN` makes it fire once.
- Docs: `docs/AGENT_RPC.md` section 17.
- Harness (`tests/harness/run_m0.py`, `reference_eval.py`): TX11 (real binary, 22 checks), an independent Python

## Unrun checks and gaps (not claimed)
- Post-commit checkpoint with no room (rollback to the pin with `post_commit_checkpoint`): the code exists, no test
  forces the condition.
- Double fault during the post-migration checkpoint retry: the commit reports `SU_E_WORKER_FAILED` while the
  migration stays in the replay log (see deviations).
- Rollback is checked by columns, schema and tick (TX11) and by "digest changed" (C test), not by digest equality
  with an independent reference of the restored state.
- Plan admission numbers are reported as estimates; they are not compared with an independent model.
- Retired-ID rule after rollback, field-ID reuse across restart, rename-only digest sensitivity, transform execution
  through the runtime: covered only by the M2-01a engine tests, not through the runtime.
- No sanitizers (ASan, UBSan, TSan) were run on the new code; TSan not applicable to the single-threaded worker.
- Native lane: not built (AsmJit absent; `tools/bootstrap_asmjit.py` would fetch third-party code, not run). Only
  the strict syntax check above. Native artifacts admitted but not installed are not tracked per world.
- 1,000,000-row migration timing: not measured. No benchmark numbers are reported.

## Deviations and decisions
1. Migration documents are given by path under the project root (`migration_path`, `transform_path`, `lir_path`);
   the inline `migration` object of the contract is not implemented.
2. Access may not grow in a migration: a replacement system that needs access the world does not grant is refused
   (`SU_E_UNSUPPORTED_MIGRATION`). The contract does not say; the successor keeps the world's stored access.
3. At most four plans per world; the oldest is replaced (documents stay spooled while a plan or log entry names them).
4. A rollback keeps the lineage and takes the union of retired IDs, minus the IDs live in the restored schema. The
   tick of a rollback may go back (restore), so the acknowledgement rule for `LOG_ROLLBACK` allows it (one revision
   bump, any tick). This changed `sync_after`; the other kinds keep the one-revision, same-tick rule.
5. The pin is replaced at each commit attempt (before the attempt is known to succeed); a failed commit leaves the
   pre-attempt state as the rollback target.
6. Commit during recovery: a death during the post-migration checkpoint recovers and retakes the checkpoint; the
   commit is then a success with `recovery`. If the retry also fails, the reply is `SU_E_WORKER_FAILED` but the
   migration stays in the replay log and is applied at the next recovery. This does not satisfy "never acknowledged"
   in that double-fault case; it is not silent (the reply says so), but it is a gap.
7. Native: installed kernels of the old schedule are released when the schedule is replaced (`su_sched_free` ->
   `su_nv_release`). Admitted-but-uninstalled kernels are not tracked per world; the install generation check refuses
   a stale one. No explicit `su_nv_release` loop was added.
8. `create_from_snapshot` and `restore_schema` build a temporary world to read the header schema (extra memory during
   the call).
9. The worker's world descriptor is built from the world's schema (unused fields included, READ). For unmigrated
   worlds this is identical to the old descriptor (verified by the existing ctest and harness).
10. Shared-file edits: `CMakeLists.txt` (link lines and the new test block only); `src/runtime/worker.c` and
    `src/agent/su_agent.c` (M2-01b code and the sync_after rollback rule). No header under `include/` changed
    (`SU_EVENT_MIGRATED` already existed).
