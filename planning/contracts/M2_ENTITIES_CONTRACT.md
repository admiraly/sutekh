# M2-00 contract draft r2: generational entities, chunked storage, structural and event queues, IR 0.2

Status: DRAFT r2 (contingent on M1 owner acceptance; additive and disabled by default until integrated). r1 was REJECTED by the independent review (`planning/handoffs/2026-10-12-m2-00-review.md`, 16 blocking items); r2 resolves each (B1..B16 are cited inline). Headers: `include/sutekh/entities.h`, `include/sutekh/ir.h` (opcodes 10..14, 0.2 constants), `include/sutekh/status.h` (`SU_E_STALE_HANDLE` = 21). `abi.h` is NOT changed. A change after acceptance needs a new generation.

## 1. Identity and storage
- `SuEntity` = `(generation << 32) | slot`. A handle is **stale** (`SU_E_STALE_HANDLE`) if its generation is 0 (any slot; so `SU_ENTITY_MAKE(5,0)` is stale, not merely zero), its slot is `>= capacity`, its slot is dead, or its generation differs from the slot's stored generation (B12). Never a lookup by slot alone. Despawn increments the stored generation; when the next generation would be `0xFFFFFFFF` the slot is **retired**: it stores `generation = SU_GEN_RETIRED`, `alive = 0`, is never reissued and never wrapped.
- **Capacity** (B3): `capacity = max(n_initial, max_entities)` where `max_entities` is an optional `world.create` parameter (fixtures omit it; default = n_initial), and `capacity <= SU_LIMIT_ROWS`. NOT rounded to chunks: chunk `c` covers `[c*1024, min((c+1)*1024, capacity))`, the last chunk may be short. Growth is a later out-of-tick transaction.
- **Chunks vs scheduler** (B4): structural/event buffers are per storage chunk (`SU_CHUNK_SLOTS`). Scheduler job slicing (`chunk_rows` in `src/runtime/jobs`) is independent; it may equal `SU_CHUNK_SLOTS` but is not required to.
- Allocation: the lowest free slot index is reused first (deterministic). A per-slot external id (u32) rides beside the generation. `su_world_create` keeps rejecting external id 0 for **fixture** entities; slots created by `world.spawn` may carry external id 0 or the given one (B11).
- **Dead slots and the alive mask** (B1), with NO `abi.h` change: the reference VM learns the alive set from its execution context (`su_vm_context_set_alive(ctx, alive_bytes, base_slot)`, set per chunk call by the runtime) and does not visit dead rows. Native kernels (IR 0.1 only) process all rows. After **every system's** `su_world_commit_staging` the runtime zeroes all columns of dead slots in the working root (`su_world_zero_dead`), so dead rows are canonically zero before the next system reads them and again at publish. Despawn (at the boundary) zeroes the slot's columns in the working root before publish; spawn writes the given field values and `0` for every other field (no schema defaults exist yet).
- **Canonical state encoding** (B2): `SUWSTATE` encoding_version 2 replaces v1 for all worlds: it covers rows `0..high_water-1` (`high_water` = 1 + highest slot ever allocated; for an M0 fixture world this is `n`) plus the entity table (per slot: generation, alive, external id), the retired count, and the free-policy name. **State dumps of M0/M1 fixture worlds therefore change**; the new expected dumps are regenerated once, committed with the change, and listed in the handoff. v1 dumps remain parseable for restore (all slots alive, generation 1). Slots `>= high_water` are implicitly dead, generation 1, zero.
- Iteration: ascending slot over alive slots.

## 2. Structural requests and events
- **Producers** (B11): control plane `world.spawn` / `world.despawn` are applied **directly between ticks** (never queued, never mid-tick), and IR 0.2 `despawn_self` / `emit_event`. There is **no spawn from IR and no template table in M2-00**; `SU_STRUCT_SPAWN` is reserved. `world.spawn` takes explicit field values.
- Systems never mutate the entity table. They append `SuStructCmd` / `SuEvent` records into **per-system, per-chunk buffers** sized at admission (B8): entries per (system, chunk) = `min(chunk_slots * max_per_row, per_tick_cap)`, preallocated; allocation during a tick is forbidden. Admission whose buffers exceed the resource budget fails with `SU_E_RESOURCE_LIMIT`.
- **Per-row cap counting** (B8): worst-case emissions per row = number of `despawn_self` + `emit_event` instructions in the module (conditions ignored, straight-line IR). Declared `max_struct_per_row` / `max_events_per_row` below the respective worst case -> `SU_E_RESOURCE_LIMIT` at **stage 5** (capsule limits, with `max_instructions`).
- **Limits sites** (B7): capsule `limits` gains optional `max_struct_per_row` and `max_events_per_row` (integers 0..64, default 0; capsules with `ir_version` 0.1 must not declare them, `SU_E_TYPE`); `schemas/capsule.schema.json` is extended accordingly. Per-tick caps (`max_struct_per_tick`, `max_events_per_tick`) and `event_log_max` are **world-creation configuration**, not capsule keys, defaults 4096 / 4096 / 65,536.
- **Multi-worker execution** (B9): an IR 0.2 module runs as one job per chunk writing only its own chunk buffers (reference VM only); any worker count yields identical merged output (test T-M2-04).
- **Merge and apply** at the tick boundary, after all systems succeeded and before publication, in canonical order `(system_index, slot, seq)` (lexicographic). Control-plane commands use `system_index = SU_SYSTEM_INDEX_HOST` and are applied directly before the tick starts, never together with IR requests. Each IR request either takes effect or is refused deterministically (despawn with a stale expected handle, e.g. two systems despawning the same entity in one tick: the second is refused). **A refused request emits a `SU_EVENT_REJECTED` record at its canonical position, consumes an `event_seq`, and counts toward `max_events_per_tick`** (B10); it never fails the tick. Successful despawns also emit `SU_EVENT_DESPAWNED`.
- Exceeding any cap (row, tick, buffer) aborts the tick with `SU_E_RESOURCE_LIMIT`: nothing is published; entity table, event log and columns stay as committed.
- **Event log** (B10): events get `event_seq` (monotonic u64, never reset) in canonical order at commit. The log is a bounded ring of `event_log_max` entries; eviction drops the oldest and increments `dropped` (part of canonical state). `events.read {world_id, cursor, max<=256}` -> `{events[], next_cursor, dropped}`: `cursor` is an `event_seq`; if it is below the oldest retained sequence the reply starts at the oldest retained record and reports the number of skipped events in `skipped`. Events are host-visible only; systems cannot consume them (later).
- Atomicity: entity table changes, event log appends, zeroing and column data publish together (committed/working roots include the entity table).

## 3. IR 0.2 (versioned extension; 0.1 modules keep working unchanged)
Opcodes (header `ir.h`, B5/B6): `slot_u32`=10, `gen_u32`=11, `tick_u32`=12, `despawn_self`=13, `emit_event`=14, with the exact operand mapping documented next to the constants: `emit_event`: `dst` = cond register (a source here), `a` = kind (const u32, any value in `0..SU_EVENT_KIND_RESERVED_MIN-1`, never an index, so no collision with `SU_OPERAND_NONE`), `b` = payload register A, `c` = payload register B. `despawn_self`: `dst` = cond register. `tick_u32` = `(committed_tick + 1) mod 2^32` (the tick being computed).
- **Verifier** (B15): stage 4 accepts `ir_version` in {`0.1`,`0.2`} and still rejects anything else with `SU_E_TYPE`; a 0.2 opcode in a 0.1 module is `SU_E_UNKNOWN_OPCODE` (stage 6); an `emit_event` kind constant `>= SU_EVENT_KIND_RESERVED_MIN` is `SU_E_TYPE` (stage 6); cap declaration checks are stage 5 (above). The `ir_version` of the IR and of the capsule must agree (`SU_E_SCHEMA_MISMATCH`, stage 5).
- **Hash** (B14): for `ir_version` 0.1 the semantic-hash input is **byte-identical to today** (test: the stored M0/M1 fixture semantic hashes are unchanged). For 0.2 the encoding is: the existing preamble but with artifact format = 2 (`SU_ARTIFACT_FORMAT_VERSION_0_2`), then profile/system/query strings and the field table as today, then the `ir_version` string (u32 length + bytes), `max_struct_per_row` u32, `max_events_per_row` u32, then the instruction count and words as today. The per-module artifact format is a **parameter of the hash**, not the global constant.
- **Native** : modules containing any 0.2 op run on the reference VM only; `world.specialize` -> `SU_E_CAPABILITY_DENIED`, reason `ir_0_2_not_lowered`. 0.1 modules are unaffected, including their native kernels (dead rows are zeroed after commit).

## 4. Snapshot and replay (B13)
Snapshot format `"0.2"` adds, after the 0.1 keys and in this fixed key order: `capacity`, `high_water`, `free_policy` (`"lowest_slot"`), `retired_count`, `slots` (array of `[generation, alive, external_id]` for slots `0..high_water-1`), `event_next_seq`, `event_dropped`, `event_log_max`, `events` (array of `[seq, tick, kind, system_index, slot, seq_in_row, a, b]`). Restore of a 0.2 snapshot reproduces handles, generations, retired slots, event log and counters exactly; the target world must have the snapshot's `capacity`. Restore of a 0.1 snapshot: the target's capacity must equal the snapshot's row count `n` (fixture default); slots `0..n-1` take the snapshot's external ids, generation 1, alive 1; `high_water = n`. Appendix (integration task): a full worked 0.2 example is committed under `tests/fixtures/` and referenced from `docs/AGENT_RPC.md`.

## 5. Control-plane methods (B16)
- `world.create` gains optional `max_entities`, `max_struct_per_tick`, `max_events_per_tick`, `event_log_max` (validated: `capacity <= SU_LIMIT_ROWS`, caps 1..1,048,576; errors `SU_E_TYPE` / `SU_E_RESOURCE_LIMIT`).
- `world.spawn {world_id, expected_world_revision, values:{<field name>: u32,...}, external_id?: u32}` -> `{world_id, world_revision, entity: <u64 handle as JSON integer>, slot, generation}`; unknown field -> `SU_E_SCHEMA_MISMATCH`; no free slot -> `SU_E_RESOURCE_LIMIT`; stale revision `SU_E_STALE_REVISION`; emits `SU_EVENT_SPAWNED`.
- `world.despawn {world_id, expected_world_revision, entity}` -> `{world_revision}`; stale/dead/retired/out-of-range handle -> `SU_E_STALE_HANDLE`; emits `SU_EVENT_DESPAWNED`.
- `world.inspect` gains optional `entity` (handle; stale -> `SU_E_STALE_HANDLE`, otherwise returns that entity's row) and always reports `entities: {capacity, alive, retired, high_water}`.
- `events.read` as in section 2. These methods are advertised in `engine.info` only when implemented. Each new mutating method is a recovery-log entry (checkpoint + replay, M1-02a).

## 6. Tests required for acceptance (M2-00)
Entity churn (>= 100,000 spawn/despawn operations against a reference model, lowest-slot reuse), stale-handle rejection (reuse, retired slot, out of range, zero, generation 0 with nonzero slot, wrong generation), generation exhaustion retirement (fault injection near the limit), canonical merge equality for worker counts 1/2/4/8 and shuffled completion orders, per-row/per-tick cap overflow aborting with unchanged state (including entity table and event log), dead slots excluded and canonically zero after native kernels staged nonzero values, snapshot 0.2 round trip incl. event log and a 0.1 restore, regenerated v2 canonical dumps for the M0/M1 fixtures, IR 0.1 semantic hashes unchanged, new-op verifier negatives with stage ordering, reference-VM known-answer cases for each new op, recovery replay of spawn/despawn, and mutation proofs for each of these.

## 6a. Rulings from the IR/VM implementation (r2.1)
- Caps are counted **per kind**: `max_struct_per_row` bounds `despawn_self` instructions and `max_events_per_row` bounds `emit_event` instructions (r2's single "sum" wording is superseded).
- A capsule may declare an optional top-level `ir_version` (absent = "0.1"); it must equal the IR's `ir_version` (`SU_E_SCHEMA_MISMATCH`, stage 5).
- Native lowering refuses **every** 0.2 module (`SU_E_CAPABILITY_DENIED`, reason `ir_0_2_not_lowered`), not only modules that use a 0.2 op.
- Rows are contiguous in a buffer: the reference VM emits a row's records together; a slot reappearing non-consecutively is repaired by the stable-sort fallback of the merge.
- A cursor ahead of `next_seq` in `events.read` is `SU_E_INVALID_ARGUMENT`. The VM trusts the caller for the lengths of the alive/generation arrays.
